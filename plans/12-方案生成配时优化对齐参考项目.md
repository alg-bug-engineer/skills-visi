# 开发计划：方案生成配时优化对齐参考项目

关联需求：`needs/12-方案生成配时优化对齐参考项目.md`
关联缺陷：本计划新增 `bugs/BUG-003-plan-timing-degenerate-min-green.md`（占位流量致配时塌缩）

## 一、目标与范围

让「方案生成」阶段产出**基于真实需求的可信配时**，达到参考项目 `traffic_signal_deepagent` 的口径：真实转向流量 + 现状配时 + 逐转向饱和度 + 逐阶段最小绿 → 优化器输出可信周期/绿信比/逐相位饱和度/强度元数据，并对数据不足/退化结果做结构化降级。

范围仅限方案生成链路与其数据准备：
- `app/optimization/request_builder.py`（占位流量/单转向/写死车道的根因）
- `app/data/load_intersection_from_pg.py`（把 `turn_flow`/`turn_saturation` 绑定进 signal 相位）
- `skills/plan-generation/scripts/run_single_point_optimizer.py`（输出增强 + 退化识别）
- `skills/plan-generation/scripts/build_candidates.py` / `handler.py`（护栏兜底 + 推荐字段一致）
- `app/api/response_builder.py`（`recommended_plan_id` 字段一致，如需要）

不改动：诊断、成因、策略选包、前端渲染契约。

## 二、现状与目标数据流

现状（退化）：
```
PG signal(现状绿/最小绿真实) ─┐
                              ├─> _build_phase_plan(占位flow=500,单转向,车道=2) ─> 优化器 ─> 14/14/14 cycle42
raw.turn_flow(真实,未绑定) ───┘（丢弃）
```

目标：
```
PG signal(现状绿/最小绿) + raw.turn_flow(按时段聚合) + turn_saturation + lane_detail
   └─> bind_turn_flows_to_stages() ─> 每阶段 phaseDirInfoDTOList[逐转向真实flow/lane/sat]
       └─> 优化器 ─> 可信 cycle/greenTime/splitRatio/phaseSaturation + meta(强度)
           └─> 退化护栏(缺饱和度/塌缩到最小绿) ─> available=false+reason
```

## 三、实现拆解

### 步骤 1：真实转向流量绑定（核心）
在 `app/data/load_intersection_from_pg.py` 新增确定性函数 `bind_turn_flows_to_signal(signal, raw, *, period)`（或在 `_assemble_task_from_raw` 内调用），职责：
- 依据目标时段把 `raw.turn_flow` 的 `step_index` 聚合为每 (link_id, turn_dir_no) 的 `turn_flow_total`（沿用现有 `step_index`↔时段映射；无映射时用 `ticket.time_range`/period 解析）。
- 合并 `raw.turn_saturation`（turn_saturation、lane_saturation_detail）与 `raw.turn_flow.lane_count`。
- 复用 `_release_movements_by_stage` 得到 stage→释放转向(link_id/dir8+turn_dir)，为每个 `phase_stage_timing_list` 项写入 `phaseDirInfoDTOList`（逐转向 `dir8No/turnDirNo/turnFlowTotal/laneCount/saturation`）。
- 绑定不到流量的转向：不编造，标注该转向 `flow_available=false`；若整阶段无流量，记录 `bind_reason`。

产物：`signal.phase_stage_timing_list[].phaseDirInfoDTOList` 为真实值；`signal.flow_binding = {ok, period, unbound_stages, reason}`。

### 步骤 2：请求构建去占位
改 `app/optimization/request_builder.py::_build_phase_plan`：
- 优先读取步骤 1 写入的 `phaseDirInfoDTOList`（真实逐转向），不足时才降级；删除 `or 500`、`or 2` 静默占位。
- 多转向阶段生成多条 `phaseDirInfoDTOList`。
- 透传真实 `greenTime / minGreenTime / maxGreenTime`（来自 PG），删除 `or 15` 类占位；车道级饱和流量从数据取，缺失时用统一常量并显式标注来源。
- `target_periods` 用工单时段。

### 步骤 3：优化输出增强
改 `run_single_point_optimizer.py::_normalize_optimizer_stages`：
- 回填每阶段 `phase_saturation`（优化器 `phaseSaturation`/强度）。
- 顶层 `timing.meta` 带 `solver`、`direction_intensity_list`、`notes`。

### 步骤 4：退化护栏
在 `run_single_point_optimizer.py`（或 `validate_plan_guardrails.py`）新增退化判定：
- 触发条件（任一）：所有阶段绿=默认最小绿且 cycle≈Σmin、`phase_saturation` 全空、优化器无 meta、cycle < 现状最小可行周期。
- 命中 → 返回 `{ok:false, reason:"配时优化输入需求缺失/结果退化", degraded:true}`，`build_candidates` 据此把该候选置为 `available=false + reason`，`handler` 不把退化结果计入 `valid_candidates`。

### 步骤 5：推荐字段一致
`handler.py`/`response_builder.py`：输出顶层 `recommended_plan_id = recommended["plan_id"]`，与 `recommendation.recommended_plan_id` 对齐。

## 八、回滚策略

- 改动均为增量函数 + 参数透传，保留原 `adjust_phase_timing` 兜底路径。
- 若绑定/优化异常，退化护栏使方案返回 `available=false + reason`，不会输出错误配时。
- 单一分支开发，问题严重时 `git revert` 本分支提交即可回到当前基线。

## 九、风险

1. **step_index↔时段映射**：需确认真实映射口径，避免时段聚合错误；无映射时按 period 解析并记录 reason。
2. **stage→转向 匹配**：`_release_movements_by_stage` 与 `turn_flow` 的 (link_id/dir8, turn_dir_no) 口径需一致，匹配失败要显式降级而非兜底占位。
3. **外部优化引擎行为**：`signal_optimization_engine` 对最小绿/饱和流的处理需以真实输入验证；若引擎仍回落最小绿，则由退化护栏兜底并暴露 reason。
4. **无 PG 本地环境**：端到端与重采可能阻塞，按 `needs/11` 先例记录阻塞，不以 mock 冒充生产。
