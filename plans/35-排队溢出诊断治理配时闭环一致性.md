## 一、实施原则

1. 先建确定性事实与契约，再改 LLM 解释层；机制与决策禁止由模型选定。
2. 全链路只允许一个目标路口、目标转向、直接下游；后续阶段禁止改写 Identity。
3. 下游承接状态唯一真源为 `blocked | slack | unknown`；叙事与前端只消费该对象。
4. 当前临时指标标记 `quality_level` / `decision_eligible`；`demo_proxy` 不得单独驱动大幅配时。
5. 证据不足时允许停在条件性/先验后调；禁止为演示强制可执行方案。
6. 方案必须证明符合 `DecisionContract`（目标有效绿净变化、周期、阶段比例、监测与回滚）。
7. 禁止 demo 静默 fallback；无数据时 `available:false` + `reason`（对齐 `docs/rule.md` 14–16）。
8. 每个阶段性失败写 `bugs/`，日志带 trace id 与关键业务 ID。

## 三、Phase 1 · 逻辑收敛（优先）

目标：即使不输出可执行配时，诊断—机制—决策自洽；Case A 停在「先验后调」。

### 3.1 唯一下游状态

新增/重构：`app/trace/downstream_decision.py`

- 输出唯一：`blocked | slack | unknown` + 证据、缺口、置信度
- 消费方：诊断、机制判别、策略、方案模板、推荐理由、前端文案

### 3.2 五类溢出机制单一判断器

新增：`app/decision/overflow_mechanism.py`

机制枚举：

| code | 含义 |
|---|---|
| `downstream_blocked` | 下游回堵型 |
| `local_release_insufficient` | 本路口放行不足型 |
| `discharge_anomaly` | 放行效率异常型 |
| `upstream_shock` | 上游冲击型 |
| `insufficient_evidence` | 证据不足型 |

规则：确定性判别，输出证据/反证/缺口/置信度；不调用 LLM 决定机制。

判别顺序对齐需求 §8.3。

### 3.3 机制 → 决策映射

策略 Skill 改为：

```text
溢出机制 → 决策矩阵 → DecisionContract → LLM 解释
```

Case A 无补充核验时：

```text
overflow_status = spillback_warning
downstream_state = slack
primary_mechanism = discharge_anomaly
decision_mode = verify_then_adjust
plan_status = conditional
executable = false
```

### 3.4 候选方案收敛

修改：`skills/plan-generation/scripts/build_candidates.py`

- 由遍历全部 `PLAN_DEFINITIONS` 改为仅 `decision.allowed_plan_types`
- 修复候选共享策略包：`package = plan_id` 或由 `DecisionContract` 逐方案生成参数

### 3.5 测试（本阶段必交）

新增：

- `tests/test_downstream_decision.py`
- `tests/test_overflow_mechanism.py`

**阶段出口：** Case A 叙事收敛为溢出预警 + 下游有余量 + 效率异常待核验 + 先验后调；无核验时不可执行。

## 四、Phase 2 · 方案一致性

目标：可生成可信的条件性/试运行配时，且语义不偏离治理意图。

### 4.1 PlanContract 与语义编译

- 目标有效绿跨搭接阶段净变化
- 供时来源、周期变化约束进入求解器
- 优化器不得覆盖治理意图（需求 §9）

### 4.2 方案语义校验

新增：`skills/plan-generation/scripts/validate_overflow_plan.py`

校验：目标有效绿净变化、周期、单阶段比例、相位映射、下游/上游对象、条件性状态、名称与动作一致性。

### 4.3 成因 / 策略 Skill 改造

- 成因：接收确定性机制 → 解释支持/反证/核验任务，不得改机制
- 策略：LLM 只解释，不再决定策略包、秒数、周期、禁止动作

### 4.4 统一状态对象与阶段转换校验

- 新增：`app/domain/overflow_case_state.py`，挂到 `SkillContext.overflow_state`
- 新增：`app/runtime/overflow_transition_validation.py`，接入 `executor.py`
- 校验对象漂移、下游覆盖、机制冲突、策略适用、方案合规、条件性误标 executable

### 4.5 测试

新增：

- `tests/test_overflow_plan_semantics.py`
- `tests/test_overflow_transition_validation.py`

fixture 显式核验通过后：`incremental_release_trial`、目标有效绿约 +5s、周期变化 0、直接下游为永绥路×齐音路。

**阶段出口：** 条件性增绿可演示；语义护栏全部通过；反向测试拒绝净减绿/周期漂移等。
