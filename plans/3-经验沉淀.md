# 开发计划：3-经验沉淀

## 背景

需求 2 已交付第九幕简化版：`POST /api/v1/agent/plan/decision` 将 accept/reject 写入 `plan_feedback.jsonl`。原计划将反馈沉淀至 `knowledge_qa.jsonl` 已废止——该文件为外部教科书案例库，**只读**。

本计划实现：

1. NLU 阶段拆分用户输入为认知/诊断/方案三类经验，完整标签化并持久化
2. 成因/策略/方案生成阶段叠加用户经验库与已接受方案库检索
3. 方案接受/否决扩展沉淀字段，否决方案用于生成阶段规避

## 目标

1. `intent_understanding` 输出 `user_experiences`，并追加写入 `user_experience.jsonl`
2. 新建 `ExperienceLibraryService`，与现有 `CaseLibraryService`（只读 `knowledge_qa.jsonl`）并列
3. 扩展 `PlanFeedbackService`，接受/否决记录含检索指纹与标签
4. `cause_analysis`、`plan_generation` 接入用户经验与方案反馈检索

## 非目标

- 写入或更新 `knowledge_qa.jsonl`
- `evaluation-feedback` Skill 全量实现（KPI 对比、迭代决策）
- 前端反馈沉淀页面
- 向量检索 / Embedding（首期关键词 + 标签 + 指纹匹配）

```json
{
  "record_id": "ue_20260707_001",
  "recorded_at": "2026-07-07T04:00:00Z",
  "trace_id": "tr_abc",
  "experience_type": "cognitive | diagnostic | solution",
  "content": "xx路口下午3点经常拥堵",
  "source_span": "xx路口下午3点经常拥堵",
  "tags": {
    "inter_id": "INT001",
    "intersection_name": "文化西路与舜华路交叉口",
    "problem_type": "拥堵",
    "time_period": "下午时段",
    "direction": null,
    "cause_dimension": null,
    "cause_keywords": [],
    "strategy_action": null,
    "related_poi": []
  },
  "diagnosis_ticket_snapshot": {}
}
```

### plan_feedback.jsonl（方案反馈库，可写，扩展 schema）

在需求 2 基础上扩展：

```json
{
  "recorded_at": "2026-07-07T04:00:00Z",
  "trace_id": "tr_abc",
  "plan_id": "plan_b",
  "decision": "accept | reject",
  "rejection_reason": null,
  "plan_snapshot": {},
  "diagnosis_ticket": {},
  "inter_id": "INT001",
  "fingerprint": {
    "problem_type": "排队溢出",
    "topology_hash": "sha256:...",
    "metrics_summary": {
      "queue_ratio_max": 0.95,
      "saturation_max": 0.88,
      "primary_direction": "东向西"
    }
  },
  "tags": {
    "primary_cause": "下游承接不足",
    "strategy_applied": "上游控流+小步释放",
    "spatial_structure": "目标路口+下游瓶颈"
  },
  "retrieval": {
    "as_recommended_case": true,
    "as_risk_case": false
  }
}
```

- `decision=accept` → `as_recommended_case=true`，供相似场景引用
- `decision=reject` → `as_risk_case=true`，`rejection_reason` 必填（或允许空但记录 `plan_snapshot`）

### knowledge_qa.jsonl（外部案例库，只读）

保持现有 `CaseLibraryService` 行为不变；新增 `ReadOnlyCaseLibraryGuard` 或在服务层禁止 `append`/`write` 方法。

## 阶段 F1：NLU 经验拆分

### F1.1 标签 schema

新建 `app/data/intersection_config/experience_tag_schema.yaml`：

- 定义三类经验的必填/可选标签
- `cause_dimension` 枚举对齐 `cause_dimension_map.yaml` 六维
- `strategy_action` 枚举：加绿、减绿、控流、协调、相位调整、渠化等

### F1.2 扩展 intent-understanding

| 文件 | 变更 |
|------|------|
| `skills/intent-understanding/resources/prompts/system.txt` | 增加三类经验拆分说明与 JSON 字段 |
| `skills/intent-understanding/references/output_schema.md` | 文档化 `user_experiences` |
| `skills/intent-understanding/scripts/extract_user_experiences.py` | 确定性后处理：补标签、校验 |
| `skills/intent-understanding/handler.py` | 调用 extract 脚本，输出 `user_experiences` |

**输出示例：**

```json
{
  "diagnosis_ticket": { "...": "..." },
  "user_experiences": [
    {
      "experience_type": "cognitive",
      "content": "文化西路与舜华路交叉口下午3点经常拥堵",
      "tags": { "problem_type": "拥堵", "time_period": "下午时段" }
    },
    {
      "experience_type": "diagnostic",
      "content": "附近有小学放学家长接送导致",
      "tags": { "cause_dimension": "event", "related_poi": ["小学"], "cause_keywords": ["接送", "放学"] }
    },
    {
      "experience_type": "solution",
      "content": "应该增加一点绿灯时间",
      "tags": { "strategy_action": "加绿" }
    }
  ]
}
```

### F1.3 经验持久化

新建 `app/services/experience_service.py`：

- `persist_from_intent(trace_id, user_experiences, diagnosis_ticket)` → 追加 `user_experience.jsonl`
- 配置项 `.env`：`USER_EXPERIENCE_PATH=data/user_experience.jsonl`

在 `AgentService.run` 意图理解完成后调用持久化（或 intent handler 内通过 deps 注入）。

## 阶段 F2：经验检索服务

### F2.1 ExperienceLibraryService

新建 `app/services/experience_library.py`：

| 方法 | 说明 |
|------|------|
| `search_cognitive(inter_id, problem_type, time_period, limit)` | 认知经验匹配 |
| `search_diagnostic(inter_id, cause_dimension, keywords, limit)` | 诊断经验匹配 |
| `search_solution(inter_id, strategy_action, limit)` | 方案经验匹配 |
| `search_all_for_context(context, limit)` | 按当前 trace 上下文综合检索 |

匹配策略（首期）：

- 路口：`inter_id` 精确 > `intersection_name` 模糊
- 问题/成因：标签交集 + 关键词重叠计分
- 时段：`time_period` 同义词表（下午/晚高峰等）

### F2.2 只读保护

`CaseLibraryService` 仅保留 `_load`、`search_*`、`count`；代码审查 + 测试断言无写路径指向 `knowledge_qa.jsonl`。

## 阶段 F3：方案反馈扩展

### F3.1 指纹与标签构建

新建 `app/services/plan_fingerprint.py`：

- `build_topology_hash(topology)`：上下游节点 ID 排序后 hash
- `build_metrics_summary(diagnosis)`：从 `data_analysis_diagnosis` 提取关键指标
- `build_feedback_tags(artifacts)`：主因、策略、空间结构

### F3.2 扩展 PlanFeedbackService

- `record_decision` 入参扩展：可选 `artifacts` 或 `topology`/`diagnosis` 片段
- 写入扩展 schema（见数据模型）
- `search_accepted_plans(fingerprint, limit)`：相似已接受方案
- `search_rejected_patterns(inter_id, problem_type, limit)`：否决记录与理由

### F3.3 API

保持 `POST /api/v1/agent/plan/decision`，请求体扩展可选字段：

```json
{
  "trace_id": "...",
  "plan_id": "plan_b",
  "decision": "accept",
  "rejection_reason": null,
  "plan_snapshot": {},
  "diagnosis_ticket": {},
  "artifacts_summary": {}
}
```

可选新增 `GET /api/v1/agent/experiences?inter_id=...` 供调试与前端列表（P2，本期可仅服务层）。

## 阶段 F4：下游 Skill 接入

### F4.1 cause-analysis

`handler.py` 变更：

```python
user_exp_refs = experience_service.search_diagnostic(...)
accepted_refs = feedback_service.search_accepted_plans(...)
# 注入 LLM prompt + 输出字段
output["user_experience_refs"] = user_exp_refs
```

成因排序时：用户诊断经验作为 `supplementary_evidence`，不覆盖 `cause_scores` 确定性结果。

### F4.2 plan-generation

`handler.py` 变更：

```python
solution_exp = experience_service.search_solution(...)
accepted_plans = feedback_service.search_accepted_plans(...)
rejected_avoid = feedback_service.search_rejected_patterns(...)
# 注入候选方案说明与 provenance
output["user_solution_refs"] = solution_exp
output["accepted_plan_refs"] = accepted_plans
output["rejected_plan_avoidance"] = rejected_avoid
```

- 用户方案经验：标注在 `candidates[].rationale` 或 `user_experience_basis`
- 已接受方案： `candidates[].provenance.accepted_plan_ref = { trace_id, plan_id }`
- 否决规避：若新生成策略与否决记录高度相似，降权或附加 `risk_warning`

### F4.3 strategy-generation（可选 P1）

检索诊断类用户经验，辅助 `strategy_instruction` 自然语言说明，不改变确定性 `strategy_package` 评分。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| LLU 拆分不稳定 | prompt + `extract_user_experiences.py` 确定性补标；测试覆盖典型句式 |
| jsonl 并发写损坏 | 单进程 append + 文件锁（或首期单 worker 文档说明） |
| 相似度误匹配 | 首期保守阈值；否决规避仅作 warning 不阻断生成 |
| 与 diagnosis_ticket 字段重复 | 经验为补充通道；工单字段仍为剧本第一幕主输出 |
