# 开发计划：2-生产化优化

## 背景

初始化后端（`plans/1-初始化后端.md`）已完成五 Skill 流水线骨架，但当前实现存在 demo 化问题：

- 诊断链路默认使用 `demo_metrics` / `demo_topology` 静默 fallback
- 方案生成仅有硬编码 `cycle_sec` + 单方向绿灯，无优化器与护栏
- 剧本第八、九幕所需字段大量缺失
- `evaluation_feedback` 未接入 pipeline

本计划以 `references/intersection/` 为生产口径真源，以 `docs/剧本.md` 为验收标准，分阶段补齐。

## 目标

1. 去除所有 Skill 生产路径上的 demo 静默 fallback
2. 方案生成接入优化器 + `validate_plan_guardrails`（最小绿、最大周期、回滚条件等）
3. 诊断数据接入 PG/MySQL（或显式 `task` 注入）
4. 剧本九幕所需结构化输出字段全部可映射
5. 新增反馈沉淀 Skill 与 API

## 非目标（本期不做）

- 前端 UI 实现
- 远程 push / CI 部署
- 完整 `traffic_signal_agent` 引擎依赖打包（可先轻量优化器 + 护栏，再逐步对齐原工程）

---

|------|------|------------------------|--------|

| 反馈沉淀（剧本第九幕） | 未实现 | `evaluation_feedback` Skill + API | P1 |

## 阶段 B：方案生成生产化

### B1. 从 references 拷贝脚本到 `skills/plan-generation/scripts/`

| 源（references，不提交） | 目标 |
|--------------------------|------|
| `calculate_phase_splits.py` | `generate_timing_plan.py`（适配本项目 task 结构） |
| `validate_plan_guardrails.py` | 原样拷贝 |
| `generate_single_point_optimization.py` | 分两步：先轻量边界优化器，再可选接原引擎 |

**轻量优化器（首期）：** 在已知 `phaseStageTimingList` + `minGreenTime` + `maxGreenTime` + 流量比下，按策略指令做小步绿信比调整（不引入完整 `traffic_signal_agent` 依赖亦可先行）。

### B2. 更新 `references/rules.md`（Skill 内）

对齐 `references/intersection/plan-generation/references/rules.md`：

- 输入：`inter_id`、`target_periods`、`phasePlanOfTimeList`
- 优化口径：联合周期 + 绿信比
- 护栏：周期 ≤ `max_cycle_s`；绿灯 ≥ `minGreenTime`；必填回滚条件

### B3. 重写 `build_candidates.py`

每个候选方案生成流程：

```
1. 根据 strategy_package 生成 strategy_instruction
2. generate_timing_plan() → PlanDraft
3. optimize / adjust splits → phaseStageTimingList
4. validate_plan_guardrails() → validation_errors
5. 若 errors 非空：plan.status = "rejected"，保留 errors 供前端展示
6. 组装完整 candidate（见 B4 schema）
```

候选方案与策略包映射：

| plan_id | strategy_package | 策略差异 |
|---------|------------------|----------|
| `downstream_protection` | `downstream_protection` | 目标方向绿信比不变或微减，禁止下游加压 |
| `incremental_release` | `incremental_release` | 目标方向 +1 步长（≤5s），从低利用率相位借绿 |
| `arterial_coordination` | `arterial_coordination` | 含上游控流点 + 相位差调整 |

### B5. 改造 `handler.py`

- LLM 仅负责 `recommended_plan_id` + `rationale`（保持现有）
- **禁止** LLM 输出具体秒数
- 推荐方案必须从 `guardrail_pass=true` 的候选中选择；若全部 rejected，返回 `success=False` 或 `needs_human_review`

### B6. 测试

| 用例 | 断言 |
|------|------|
| `test_plan_guardrail_rejects_below_min_green` | 绿灯 < minGreen → validation_errors |
| `test_plan_guardrail_rejects_over_max_cycle` | 周期超限 → errors |
| `test_plan_requires_rollback_condition` | 缺回滚 → errors |
| `test_plan_candidate_full_schema` | 含 phase_stage_timing_list |
| `test_recommended_only_from_valid_candidates` | 不推荐 rejected 方案 |
| `test_pipeline_e2e_with_signal_fixture` | fixture 配时数据跑通 |

**验收：** 剧本口播「最小绿灯、最大绿灯、黄灯全红、行人过街、下游溢流风险」均有 `validation_errors` 或 `guardrail_pass` 可展示。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| PG 环境本地不可用 | `task` 注入 + `tests/fixtures/`；CI 用 fixture，不用 demo 静默 fallback |
| 原优化引擎依赖重 | 首期轻量边界调整器 + 护栏；引擎可用时切换 |
| LLM 编造秒数 | 秒数仅来自脚本；LLM 只选 plan_id |
| 案例库格式不统一 | 反馈 API 定义写入 schema；旧库只读 |
