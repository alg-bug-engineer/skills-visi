# 计划6 · 流式渐进演出（SSE 边算边渲染）

对应需求：`needs/6-流式渐进演出.md`。分支：当前 `20260707140643-5-前端UI九幕演示`（延续开发）。

## 架构总览

```
后端  executor.iter_pipeline (async gen, 逐 skill yield)
        └─ AgentService.run_stream → 每步构建 public snapshot
              └─ routes POST /agent/run/stream  → StreamingResponse(SSE)
前端  api/sse.ts (fetch+ReadableStream 解析, 重连/abort)
        └─ endpoints.runAgentStream(handlers)  (MOCK 时按 phase 模拟推送)
              └─ store: 事件驱动 + phase 门控 + waiting
                    └─ ProcessPanel 门控推进 / Dock 等待态
```

关键设计：`phase_done.snapshot` 每次是**完整公开响应**（截至当前），前端**整体覆盖** store，卡片读 getters 自动更新；幕推进以"该幕所属 phase 是否已在 `response.phases` 中"为门控，故**同一套逻辑天然兼容**流式与单次 JSON（单次时全 phase 一开始即在）。

## 阶段拆解

### B0 后端流式内核
- `app/runtime/executor.py`：抽出 `async def iter_pipeline(...) -> AsyncIterator[dict]`，每完成一个 skill `yield {"type":"phase","skill_id","phase","success","duration_ms","results","artifacts"}`；末尾 `yield {"type":"final", ...}`（含 `completed/pipeline_complete`）。`run_pipeline` 改为消费该生成器返回聚合，保证旧行为不变。
- `app/api/response_builder.py`：新增 `build_public_snapshot(trace_id, artifacts, results, task)`，复用 `build_public_run_response` 的结构（已能处理部分 artifacts），补 `diagnosis_ticket` 富化逻辑。
- `app/services/agent_service.py`：新增 `async def run_stream(...)`，委托 `executor.iter_pipeline`，每步产出 `(event_type, payload)`；富化 diagnosis_ticket 与 `run` 保持一致。

### B1 SSE 路由 + 事件协议
- `app/api/routes.py`：新增 `POST /agent/run/stream`，`StreamingResponse(gen, media_type="text/event-stream")`，`headers={"Cache-Control":"no-cache","X-Accel-Buffering":"no"}`。
- SSE 帧：`event: <phase_start|phase_done|pipeline_complete|error>\n` + `data: <json>\n\n`。
- 校验沿用 `validate_pipeline_request`；异常转 `error` 事件而非 500（已进入流后）。

### B2 后端测试
- `tests/`（pytest + httpx/异步）：
  - 事件顺序：`phase_start`→`phase_done`×5→`pipeline_complete`；每个 `snapshot.phases` 单调增长。
  - 部分失败：mock 某 skill 抛错 → 出现 `error` 且不再有后续 phase。
  - `build_public_snapshot` 增量正确、`pipeline_complete` 末次为真。
- 用 `LLM_MOCK=true` 跑，避免真实 LLM 依赖。

### B3 前端 SSE 客户端 + MOCK 模拟
- `src/api/sse.ts`：重写为 `streamPost(path, body, {onEvent, signal})`——`fetch` POST → `res.body.getReader()` → 按 `\n\n` 切帧、解析 `event:`/`data:`；最多 3 次重连（指数退避），`onFail` 交上层降级。
- `src/api/endpoints.ts`：`runAgentStream(userInput, handlers, opts)`；`VITE_MOCK=1` 时读 fixture，按 `PHASE_ARTIFACT_KEYS` 拆分，`setTimeout` 依次 emit `phase_done`（含逐步 snapshot），最后 `pipeline_complete`。

### B4 前端时间线改造（事件驱动 + 门控）
- `src/composables/useTimeline.ts`：由 `buildActs(resp)`（narration 内联）重构为**静态 `ACT_DEFS`**（新增 `phase` 字段）+ 纯函数 `narrationFor(act, resp)`。
- `src/stores/presentation.ts`：
  - `mode: 'stream' | 'batch'`；`waiting: boolean`；`applySnapshot(snap)` 覆盖 response（不重建 acts）。
  - `phaseReady(phase)`：查 `response.phases[phase]`（plan 幕查 `response.plan`）。
  - `startRunStream()`：起流；首个 `phase_done(intent)` 到达 → `currentAct=0`。
  - `tryAdvance()`：进入下一幕前检查 `phaseReady`；未就绪 → `waiting=true`；`applySnapshot` 后若 `waiting && phaseReady(next)` → 清除并推进。
  - 失败：`onStreamError(phase)` → 标记失败幕、停推进、Toast。
  - 降级：`onFail` → 调 `runAgent` 单次，`mode='batch'`，走旧假节奏。
- `src/panels/ProcessPanel.vue`：`lines = narrationFor(activeAct, response)`；打字完成后调 `store.tryAdvance()`（含门控），不再无条件定时推进。
- `src/panels/BottomDock.vue`：运行态在 `waiting` 时显示"（阶段名）推演中…"脉冲；signal 反映流状态。

### B5 联调 / 降级 / 测试 / 文档
- 真机联调：后端 `LLM_MOCK=false`；前端 `VITE_MOCK=0` 走 `/agent/run/stream`。
- 降级演练：断开后端 → 自动回退单次 JSON。
- 更新 Vitest：`narrationFor`、`phaseReady/tryAdvance` 门控、MOCK 流式 emit 顺序、降级分支。
- 更新 Playwright：流式（MOCK）下断言证据卡"逐步"出现（先 1 张，后增多）、等待态可见、无遮挡。
- 更新 `frontend/README.md`（流式端点 + `VITE_MOCK` 模拟说明）、`plans/6` 进度、必要时 `bugs/`。

## 风险与缓解
| 风险 | 缓解 |
|------|------|
| SSE 经代理被缓冲不实时 | 设 `X-Accel-Buffering: no` + `Cache-Control: no-cache`；Vite 代理默认不缓冲 |
| 快照整包重发偏大 | phase 数少（5），单包可接受；必要时后续改增量 |
| acts 重建导致打字重启 | acts 静态化，仅覆盖 response，narration 按需计算 |
| 部分失败/断连状态错乱 | 明确状态机（running/waiting/error/done）+ 复用 `phase_results` |
| 流式与 batch 双路径分叉 | 门控逻辑以 `response.phases` 存在性统一，两路复用 |

### 关键取舍
- 快照**整包重发**（phase 仅 5，单包可接受）→ 前端整体覆盖、卡片经 getters 自动更新，避免 diff 复杂度。
- 门控以「快照 `phases` 是否含该幕 phase」判定，**流式与单次 JSON 复用同一套逻辑**（单次时全就绪，门控为 no-op）。
- 自动化环境（`navigator.webdriver`）下打字机即时完成，保证 e2e 稳定；真实用户仍走打字动画。
- `regenerate/accept/reject` 维持请求-响应，返回后就地覆盖快照（后续可再改流式）。
