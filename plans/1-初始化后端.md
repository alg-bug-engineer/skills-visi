# 开发设计：1-初始化后端

## 目标

基于 Qwen API 实现交通智能体后端，通过 Skill Runtime 串联五个技能，完成「排队溢出」演示剧本的完整诊断链路。

## 技能映射

| 技能 ID | 名称 | 参考来源 | 剧本阶段 |
|---------|------|----------|----------|
| `intent_understanding` | 意图理解 | 剧本第一幕、沟通文档 | 问题理解 → 诊断工单 |
| `data_analysis_diagnosis` | 数据分析与诊断 | references/scene-cognition | 溢出验证、指标计算 |
| `cause_analysis` | 成因分析 | references/problem-diagnosis | 主因判断、案例佐证 |
| `strategy_generation` | 策略生成 | references/control-strategy | 治理策略原则 |
| `plan_generation` | 方案生成 | references/plan-generation | 可执行配时方案 |

## 架构

```
app/
  runtime/
    skill_types.py   # Skill 基类与上下文
    skill_loader.py  # 解析 SKILL.md frontmatter，校验目录结构
    registry.py      # 扫描 skills/*/ 目录发现并注册
skills/              # 标准文件夹：SKILL.md + scripts + references + resources
  intent-understanding/
    SKILL.md
    handler.py
    scripts/
    references/
    resources/
tests/
```

### Skill 文件夹规范（对齐 references 标准）

每个技能一个目录，**必须**包含：

```
skills/<skill-name>/
  SKILL.md        # YAML frontmatter + 正文（禁止只有 frontmatter）
  handler.py      # 运行时执行入口
  scripts/        # 确定性脚本
  references/     # 规则、阈值、输出 schema 等参考文档
  resources/      # 提示词、演示数据等资源
```

`rule.md` 第 9 条「禁止单独的 md 文档」含义：**禁止 Skill 仅有 md 而无 scripts/references/resources**，不是禁止使用 `SKILL.md`。

## 核心指标（溢出场景）

- 排队比 = 排队长度 / 进口道蓄车长度
- 阈值：≥0.8 溢出预警，≥1.0 明确溢出风险（借鉴 thresholds.yaml `spillback.risk_high`）
- 辅助：饱和度、绿灯利用率、下游排队比、上游来车强度

## API 设计

- `POST /api/v1/agent/run` — 提交自然语言问题，执行完整流水线
- `GET /api/v1/agent/skills` — 列出已注册技能
- `GET /api/v1/health` — 健康检查

## 测试策略

- 使用剧本示例输入做端到端测试（mock LLM）
- 各 Skill 独立单元测试
- 指标计算确定性测试
- 日志 trace_id 传递测试

## 配置项（.env）

- `LLM_MOCK=true` 测试模式
