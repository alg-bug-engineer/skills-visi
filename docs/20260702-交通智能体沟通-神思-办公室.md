智能体流程梳理
1、问题理解：这是什么问题
需要包含的维度
- 对向：路口、干线
- 问题：拥堵、失衡、空放、溢出、冲突、协调（停车频繁）
- 补充信息：时间、方向、约束
2、数据分析：分析问题需要哪些数据
- 每一类问题，需要从哪些表、拉取哪些数据
- 拉取的数据时间窗口、粒度情况
3、问题诊断：问题验证、核查
- 业务指标是否满足，拥堵需要关注的指标逻辑表达式是否成立等
- 是对基础指标的组合
4、成因分析
- 这个路口确实拥堵，这个拥堵是什么原因造成的？上游流量过大？相位配时不足？从点到线核查一遍，给出合理的解释
- 这个路口确实存在空放，空放是什么原因造成的？
- 失衡
- 溢出
- 流量溯源、路径拓扑
5、策略生成
- 是偏理论、定性和少量定量的表达，是一种指导方案，不是具体的执行动作，比如
- **针对东西南北四个进口直行需求占比80%-93%、左转仅7%-19%、右转为零的特征，实施绿信比重构，压缩左转相位配时、强化直行方向通行权保障**
6、方案生成
- 具体的执行动作，比如绿灯减少多少秒

分析逻辑：
1、要有方案，形成闭环
2、选择示范路口，包括当前路口有优化空间和路口无优化空间需要选干线的
3、问题选择是溢流，溢流风险的定义：排队长度/进口道长 > 0.8
4、尽量补充高点视频，端正存在抽帧结果
5、要进行流量下游溯源，用于计算下游的风险

任务确认：
- 端正：确定视频抽帧情况，存在图片
- 亚楠：下游流量溯源情况，确认了，存在流量去向溯源情况
- 颖超：筛选有溢出风险的进口道路口、转向级（需要带方向、时段）

路口诊断思路：
宏观思路：
结合路网拓扑信息，分析当前路口和直接下游路口，以及流量溯源的来源路径，从而形成整
体、宏观、全面的诊断
诊断细节：
1、根据用户表达，定位到具体的路口（目标路口）
2、根据路网拓扑情况，分析出目标路口直接下游路口（直接到达的一跳的路口）
3、拉取数据，分析目标路口和直接下游路口的维度包括溢出、拥堵情况
4、计算目标路口的流量去向溯源（一跳），计算当前路口到下游的直行、左转、右转流量占比
5、如果直接下游路口存在优化空间，那么当前路口理论上可以通过信控减少部分流量
6、如果下游也存在饱和，没有优化空间了，则进行流量来源溯源，进行干线协调
7、添加路口的抽帧视频，补充验证路口的问题
8、最终生成治理方案

实现细节：
1、目标路口的溢出如果是转向粒度，比如左转或者直行，那么去向是不是就已经确定了，也就是直接下游，以东西南北十字路口为例，西进口左转的流量，理论都去了北出口
2、直接下游的拥堵、排队、饱和度情况，是转向级别的情况下，可能存在左转不饱和，直行饱和了，这种情况下，不能往下游释放流量了，避免释放的流量让直行溢出

反馈和迭代逻辑，对于生成的方案，如果用户：
- 接受：则沉淀到案例库，case
	- 效果好：good case
	- 效果差：bad case
- 拒绝：沉淀案例库，bad case
	- 有评论，为什么拒绝
	- 无评论

案例的作用：
- 成因分析：交通问题诊断
- 策略生成：对应治理方案

skill
- 场景理解 skill
	- 定位：提供对问题全面的理解分析
- 分析和诊断 skill
	- 定义基础指标和业务指标
	- 提供业务问题判断
- 成因分析 skill
	- 定位：基于指标情况，给出问题的分析思路、方向、维度等，生成结论
	- 流量溯源
- 策略生成 skill
	- 根据结论，结合业务知识，生成治理策略
- 方案生成 skill
	- 根据策略，进行量化，生成具体的执行动作
