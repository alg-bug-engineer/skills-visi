# 前端集成指南

> 对应需求 4。字段路径详见 `docs/剧本字段-API对照.md`。  
> 首次拉仓部署请先看 [`docs/部署指南.md`](./部署指南.md)。

## 1. 环境变量

| 变量 | 演示联调 | 生产 |
|------|----------|------|
| `LLM_MOCK` | `true` | `false` |
| `ALLOW_DEMO_FALLBACK` | `true` | `false` |
| `PG_DSN` | 可选 | **必填**（或 BFF 注入 `task`） |
| `QWEN_API_KEY` | 可空（mock） | 必填 |

启动：

```bash
source .venv/bin/activate
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 2. 快速开始（三步）

### 2.1 健康检查

```http
GET /api/v1/health
```

响应含 `pg_configured`，用于判断能否调用路口加载。

### 2.2 加载路口数据（生产推荐）

```http
POST /api/v1/intersection/load
Content-Type: application/json

{
  "intersection_name": "文化西路与舜华路交叉口",
  "time_range": "18:10-18:30",
  "direction": "东向西",
  "movement": "直行"
}
```

成功时 `task` 可直接作为下一步 `POST /api/v1/agent/run` 的 `task` 字段。

检查单进度（可选 SSE）：

```http
POST /api/v1/intersection/load/stream
```

### 2.3 运行智能体

```http
POST /api/v1/agent/run
Content-Type: application/json

{
  "user_input": "文化西路与舜华路交叉口，六点十分到六点半，东向西排队溢出到上游，优先避免下游继续外溢。",
  "trace_id": "demo-001",
  "task": {}
}
```

生产环境将上一步 `load` 返回的 `task` 并入请求。

## 3. 分步执行（对齐剧本底部任务栏）

### 3.1 仅执行到意图理解

```json
{
  "user_input": "…",
  "trace_id": "demo-001",
  "stop_after": "intent_understanding"
}
```

### 3.2 续跑后续阶段

将上一轮响应中的 `phases` 写回 `task.artifacts`（使用内部 skill 键名）：

```json
{
  "user_input": "",
  "trace_id": "demo-001",
  "task": {
    "artifacts": {
      "intent_understanding": { "...": "..." },
      "data_analysis_diagnosis": { "...": "..." }
    },
    "diagnosis_ticket": { "...": "..." },
    "metrics": { "...": "..." },
    "topology": { "...": "..." },
    "signal": { "...": "..." }
  },
  "skill_ids": ["cause_analysis", "strategy_generation", "plan_generation"]
}
```

### 3.3 响应语义

| 字段 | 含义 |
|------|------|
| `completed` | **本次请求**执行的 skill 是否全部成功 |
| `pipeline_complete` | 五段默认流水线是否均已有 artifact（含续跑累积） |
| `phase_results[]` | 本次执行各阶段耗时与错误 |

## 4. 九幕与 API 映射

| 幕 | 主要数据来源 |
|----|--------------|
| 一 | `diagnosis_ticket` |
| 二 | `phases.intent.spatial_scene`（需 `topology`） |
| 三 | `phases.diagnosis.metrics`、`overflow_verification`、`scenario_report` |
| 四 | `phases.diagnosis.downstream_diagnosis` |
| 五 | `phases.diagnosis.arterial_analysis`、`map_scenes` |
| 六 | `phases.cause` |
| 七 | `phases.strategy.strategy`（含 `recommended`、`hard_constraints`） |
| 八 | `plan`（含 `recommendation.rationale`） |
| 九 | `POST /agent/plan/decision`、`GET /agent/cases`、`POST /agent/plan/regenerate` |

## 5. 失败态展示约定

- `completed=false`：查看 `phase_results` 最后一项的 `errors`
- `phases.diagnosis.available=false`：展示 `reason`，提示检查 PG / `task` 注入
- `intersection/load` 返回 `ok=false`：展示 `reason`（如 `pg_dsn_not_configured`）

## 6. 地图字段约定

- 坐标：`lng` / `lat`（WGS84）
- `phases.intent.spatial_scene.highlight_path`：坐标点数组 `[[lng, lat], ...]`
- `phases.diagnosis.map_scenes`：按阶段切换 `downstream_trace_map`、`arterial_analysis`

## 7. 方案反馈与再生成

接受/拒绝：

```http
POST /api/v1/agent/plan/decision
```

修改后再生成：

```http
POST /api/v1/agent/plan/regenerate

{
  "trace_id": "demo-001",
  "user_input": "保持下游保护，小幅增加东向西绿灯",
  "task": { "artifacts": { "...": "..." } },
  "restart_from": "plan_generation"
}
```

近期案例列表：

```http
GET /api/v1/agent/cases?problem_type=排队溢出&limit=20
```

`category` 可选：`textbook` | `recommended` | `risk`。
