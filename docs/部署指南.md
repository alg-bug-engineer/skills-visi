# 部署与本地启动指南

面向首次拉取本仓库的开发者：从依赖安装到三种常用启动路径（前端 Mock、本地联调、PG 真源）。

## 1. 环境要求

| 依赖 | 建议版本 | 说明 |
|------|----------|------|
| Python | 3.11+ | 后端 FastAPI；建议使用项目 `.venv` |
| Node.js | 20+ | 前端 Vite；`npm` 随 Node 安装 |
| PostgreSQL | 可选 | 路径 C 真源联调需要网络可达的库 |
| 高德 JS API Key | 地图演示需要 | 向团队索取，填入 `frontend/.env.local` |
| Qwen / DashScope Key | 真实 LLM / TTS 需要 | Mock 路径可不填 |

## 2. 克隆与安装依赖

```bash
git clone <本仓库 URL>
cd traffic-agent-0706-zql

# 后端
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install -r requirements-dev.txt   # 跑 pytest 时需要

# 前端
cd frontend && npm install && cd ..
```

## 3. 配置文件

密钥**不要提交**。向团队索取高德 Key、Qwen Key、PG 连接信息后，写入本地 env。

### 3.1 后端（项目根目录）

```bash
cp .env.example .env
```

常用项（完整列表见 `.env.example`）：

| 变量 | Mock / 演示 | PG 真源联调 |
|------|-------------|-------------|
| `QWEN_API_KEY` | 可空（配合 `LLM_MOCK=true`） | 真实推演必填 |
| `LLM_MOCK` | `true` | `false` |
| `ALLOW_DEMO_FALLBACK` | `true`（无 PG 时可演示） | `false` |
| `PG_DSN` | 可空 | **必填**（见 §6） |
| `PG_SCHEMA` | 默认 `road6` | 按环境 |
| `PG_FLOW_SCHEMA` | 默认 `xianchang` | 按环境 |

### 3.2 前端（`frontend/`）

```bash
cd frontend
cp .env.example .env.local
```

| 变量 | 说明 |
|------|------|
| `VITE_AMAP_KEY` / `VITE_AMAP_SECURITY` | 高德 JS API 2.0；勿提交 |
| `VITE_API_TARGET` | 后端地址，默认 `http://localhost:8000` |
| `VITE_MOCK` | `1` = 离线回放 fixture；`0` = 调真实后端 |

## 4. 路径 A：前端 Mock 离线（最快验证 UI）

不启动后端，用 `frontend/src/mock/` 真实响应回放。

```bash
cd frontend
# .env.local 中：VITE_MOCK=1，并填好高德 Key
npm run dev
# 浏览器打开 http://localhost:5173
```

适合改 UI / 运镜 / 卡片，不依赖 Qwen 与数据库。

## 5. 路径 B：本地前后端联调

### 5.1 推荐一键启动

```bash
# 根目录 .env：建议先 LLM_MOCK=true、ALLOW_DEMO_FALLBACK=true（无 PG 时）
bash scripts/start-all.sh
```

脚本会后台起后端（默认 `8000`）、等待 `/api/v1/health`，再前台起前端（默认 `5173`）。`Ctrl+C` 同时停两侧。

也可分终端：

```bash
bash scripts/start-backend.sh
# 另一终端
# frontend/.env.local：VITE_MOCK=0
bash scripts/start-frontend.sh
```

端口占用时脚本会尝试释放；也可用 `BACKEND_PORT` / `FRONTEND_PORT` 覆盖。

### 5.2 健康检查

```bash
curl -s http://localhost:8000/api/v1/health
# 期望含 "status":"ok"；关注 llm_mock、pg_configured
```

### 5.3 演示开关说明

| 模式 | 配置要点 | 行为 |
|------|----------|------|
| 规则 Mock LLM | `LLM_MOCK=true` | 不调 Qwen，流水线可跑通 |
| Demo 回退 | `ALLOW_DEMO_FALLBACK=true` | 无 PG 时可用内置/fixture 演示数据 |
| 真实 LLM | `LLM_MOCK=false` + `QWEN_API_KEY` | 各 phase 可能数秒返回，属正常 |

前端必须 `VITE_MOCK=0` 才会请求后端。

## 6. 路径 C：PostgreSQL 真源联调

生产默认：**有 PG 或由 API `task` 注入**；禁止静默用 demo 冒充生产数据。

### 6.1 `PG_DSN` 格式

使用 **psycopg 3** 的 libpq 关键字串（空格分隔），不要用未编码的 URL 形式：

```env
PG_DSN=host=示例主机 port=15432 user=示例用户 password=你的密码 dbname=示例库
PG_SCHEMA=road6
PG_FLOW_SCHEMA=xianchang
ALLOW_DEMO_FALLBACK=false
LLM_MOCK=false
```

密码含 `@` 等特殊字符时，直接写在 `password=` 后即可（无需 URL 编码）。

具体主机与账号向团队索取；仓库内若存在本地 `docs/postgresql_info.md`，该文件已 gitignore，不会随克隆下发。

### 6.2 连通性自检

```bash
source .venv/bin/activate
python -c "
from dotenv import load_dotenv
load_dotenv()
from app.data.pg_client import read_pg_rows
print(read_pg_rows('SELECT current_database()', {}))
"
```

可选：嗅探有配时覆盖的路口（产出本地 JSON，便于挑联调路口）：

```bash
python -m app.data.pg_signal_sniffer
```

### 6.3 预期行为

- `ALLOW_DEMO_FALLBACK=false` 且未配 `PG_DSN`、请求也未注入 `task`：路口注册表 / 诊断 fixture 不可用。
- PG 可达但某路口指标缺失：诊断 Skill 返回 `available: false` 等，**不会**静默填 0 或 demo。
- 健康检查中 `pg_configured` 应为 `true`。

启动方式同路径 B；前端 `VITE_MOCK=0`。

## 7. 验证清单

- [ ] `curl` 健康检查返回 `status: ok`
- [ ] 浏览器打开 `http://localhost:5173`，地图能加载（高德 Key 有效）
- [ ] Mock 路径：点「开始推演」能走完九幕回放
- [ ] 联调路径：`VITE_MOCK=0`，推演能打到后端（Network 可见 `/api/v1/agent/...`）
- [ ] PG 路径：换真实路口名/时段后，诊断不再整段 demo 占位
- [ ] （可选）用 [`典型输入案例-点线优化.md`](./典型输入案例-点线优化.md) 中的一句话 query 试跑

## 8. 常见问题

| 现象 | 处理 |
|------|------|
| 端口 8000/5173 被占 | 脚本会尝试 kill；或改 `BACKEND_PORT` / `FRONTEND_PORT` |
| 地图空白 / Key 报错 | 检查 `frontend/.env.local` 高德项；重启 `npm run dev` |
| 前端无数据、不调后端 | 确认 `VITE_MOCK=0`，且后端已起 |
| 健康检查 `pg_configured: false` | 检查根目录 `.env` 的 `PG_DSN` 是否加载（改完需重启 uvicorn） |
| 真源下诊断空 / available false | 路口名是否在库中、时段是否有指标；勿开 Demo 回退冒充 |
| TTS / 语音失败 | 检查 `QWEN_API_KEY` 或 `DASHSCOPE_API_KEY`；可先 `TTS_ENABLED=false` |
| pytest 找不到包 | 在项目根、已 `source .venv`，执行 `.venv/bin/python -m pytest tests/ -q` |

## 9. 本地打包（含 env）

需要把当前工作区打成可拷贝压缩包（**含** `.env` / `frontend/.env.local` 等，**不含** `references`、`.venv`、`.pytest_cache`、`frontend/node_modules`、`frontend/playwright-report`）：

```bash
bash scripts/package-local.sh
# 产物：dist/traffic-agent-local-<时间戳>.tar.gz
```

产物含密钥，勿公开分发、勿提交 git（`dist/` 已 gitignore）。
