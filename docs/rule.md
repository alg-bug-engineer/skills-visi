1. 每次新增需求，需要新开分支，分支命名是：yyyymmddhhmmss-index-需求概述的形式，开发完成后，禁止直接合入 main
2. 分支开发，主干发布的逻辑
3. 项目使用根目录的 .venv 虚拟环境，避免和系统冲突
4. 需要开发前要填写详细的开发设计和计划，以及对应的单元测试，如果设计改动，要及时更新单元测试，避免陈旧导致的冲突
5. 所有的日志落到 logs 文件夹，要详细带 trace id，便于日志审计、调试、排查问题；
6. 这是本地仓库，不考虑远程 push 的逻辑。
7. knowledge_qa.jsonl 是案例库
8. 剧本.md 是整个系统的叙事逻辑线，这只最终要达到的叙事逻辑
9. 基于 Qwen 开发的交通智能体，基于 skills 逻辑，要实现 skill runtime 的发现、注册等运行时，每个 skill 禁止单独的 md 文档
10. 使用.env 进行各类变量、密钥等配置
11. references 是各类参考资源，禁止 import 方式使用，可以拷贝、借鉴其逻辑，禁止提交 git
