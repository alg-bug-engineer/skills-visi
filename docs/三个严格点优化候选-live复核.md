## 4. 发现的实现问题

### 4.1 花园东路库容选择未取方向内 MIN

严格筛选 SQL 对每个进口采用 `MIN(length_m)`，得到西进口 92.30m；live 的 `_storage_for_dir8` 当前取第一个匹配明细，得到 345.60m。相同方向存在多条入口 link 时会产生口径漂移。

### 4.2 排队比错误依赖饱和度可用性

三个案例均缺目标转向饱和度。现有 profile 在 `metrics_available=false` 时同时清空 queue_ratio，导致已有真实排队和库容也无法形成排队比。排队空间验证与饱和度验证应分别标记可用性。

### 4.3 下游转向被硬编码为直行

`enrich_downstream_metrics` 构造下游 ticket 时固定 `movement="直行"`。对西进口左转 Case，应沿拓扑传递 `receiving_turn_dir_no=1` 并读取南进口左转，而不是南进口直行。

### 4.4 跨周峰值与单日 live 口径不同

筛选统计覆盖 2026-06-08 至 2026-06-14 的晚高峰峰值；live 默认读取周五典型日窗口。龙鼎南直跨周峰值比为 0.9256，但周五 `queue_len_avg` 峰值仅 25.40m，对应 0.4228。若演示严格峰值案例，live 必须携带筛选峰值的日型，或明确展示“跨周筛选峰值”和“所选典型日”两套值。

## 5. 结论

1. **首选：花园东路×奥体中路西进口直行。** 原子数据最强且均值比 0.4003，排队型典型性最好；修复库容选择、排队比独立可用和下游库容注入后可作为正式点优化演示。
2. **备选：花园东路×奥体中路西进口左转。** 原子数据满足，但峰值余量较小，且当前 live 下游转向绑定错误，修复前不能使用。
3. **观察案例：龙鼎大道自交南进口直行。** 原子峰值满足、拓扑绑定基本正确，但均值较低且周五不复现跨周峰值，更适合说明“瞬时峰值候选”，不建议作为首个正式典型。
4. 三个案例均缺少可用的现状配时，当前只能验证“是否具备点优化数据条件”，还不能验证具体加绿秒数或生成完整可执行方案。
