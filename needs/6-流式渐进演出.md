# 需求6 · 流式渐进演出（SSE 边算边渲染）

## 背景与问题

现状 `/agent/run` 串行跑完整条流水线（意图→诊断→成因→策略→方案，多次 LLM 调用）后**一次性**返回，前端再用定时器"假装"逐幕揭示。真实联调时用户先对空屏干等数十秒，再看一段早已算完的动画——**所有等待都堆在最前、且屏幕空白**，是最差的延时曲线。

## 目标

采用**路径 B（服务端流式）**一步到位：后端每完成一个 phase 就把该 phase 的结果推给前端，前端**边算边渲染**——第一张证据卡在意图阶段完成后（几秒）即出现，后续 phase 的计算与前端当前幕的动画重叠，用"错位"掩盖步间延时。

非目标 / 明确边界：
- 流水线各 phase **有链式依赖**（下一步读取上一步 artifacts），故**不缩短总计算时间**，只优化"首屏时间 + 感知延时"。
- 掩盖是**部分的**：若某 phase 计算时间 > 当前幕动画时间，用户仍会在"推演中"停留剩余时间。这是可接受且诚实的表现（Dock 显示真实等待态）。

## 功能需求

- FR-1 新增流式接口 `POST /api/v1/agent/run/stream`，SSE（`text/event-stream`）逐 phase 推送；保留 `POST /agent/run` 作为兜底。
- FR-2 事件协议（`event:` + `data: <json>`）：
  - `phase_start`：`{skill_id, phase, index, total}`
  - `phase_done`：`{skill_id, phase, index, total, success, duration_ms, snapshot}`，其中 `snapshot` 为**截至当前**的完整公开响应（与 `/agent/run` 同结构，仅 `phases`/`plan` 逐步补齐）。
  - `pipeline_complete`：`{snapshot}`（最终快照，含 `pipeline_complete=true`）。
  - `error`：`{skill_id, phase, errors}`，随后结束流。
- FR-3 单个 skill 失败时：推 `error` 事件并停止（对齐现有 `break` 语义），前端把该幕标记失败、停在已到达进度、展示已完成部分。
- FR-4 前端演出改为**事件驱动**：某 phase 数据到达前，属于该 phase 的幕不允许进入，Dock 显示"（某阶段）推演中"等待态；数据到达后自动推进。phase 内的多个子幕仍由前端节奏补速。
- FR-5 幕↔phase 映射：意图→幕1/2；诊断→幕3/4/5；成因→幕6；策略→幕7；方案→幕8/9。
- FR-6 离线（`VITE_MOCK=1`）下用 fixture **模拟流式**（按 phase 分片 + 延时推送），保证无后端时也能演示这套交互。
- FR-7 优雅降级：流式不可用/解析失败/断连超重试，回退到 `/agent/run` 单次 JSON + 现有假节奏（保留旧路径）。
- FR-8 可取消：切换/重置时中断流（AbortController），后端应处理客户端断开。
- FR-9 `accept/reject/regenerate/cases` 维持请求-响应；`regenerate` 返回后按方案 phase 就地重放（后续可再改流式）。

## 非功能需求

- NFR-1 快照可**增量替换**：前端每次收到 `snapshot` 直接覆盖 store，getters/卡片随之更新，无需 diff。
- NFR-2 不编造：phase 未到达即"数据暂缺"占位（延续 rule 14）。
- NFR-3 事件与日志复用现有 `trace_id`，便于串联排查。
- NFR-4 dev 免 CORS（Vite 代理已覆盖 `/api`）；SSE 走同一代理。

## 验收标准

- AC-1 真实后端下，`curl -N /api/v1/agent/run/stream` 能看到按序 `phase_start/phase_done ...pipeline_complete` 事件，且每个 `phase_done.snapshot` 比上一个多一个 phase。
- AC-2 前端真实联调：工单卡在意图完成后即出现，不必等整条流水线；后续幕随各 phase 到达推进，等待期 Dock 显示对应"推演中"。
- AC-3 某 phase 失败时前端不崩、停在部分结果并提示。
- AC-4 断网/流式失败自动回退单次 JSON 路径仍可完成九幕。
- AC-5 `VITE_MOCK=1` 模拟流式演出可完整走完九幕。
- AC-6 pytest（后端事件顺序/部分失败/增量快照）+ Vitest（映射/门控/降级）+ Playwright（流式下证据卡逐步出现、无遮挡）全绿。
