# 需求9 · 标准流量溯源、下游十字拓扑与 zoom18 渠化指标可视化

## 背景

当前项目已有需求8的流量溯源图层与防闪运镜改造，但仍缺两块用户可验收结果：

- 流量溯源必须严格替换为 `references/流量溯源/sniff/flow-trace-links-sniff.html` 的标准链路表达：真实 link 几何、主链/其他链分色、发光双层、粒子、节点占比标签，不能再像普通线段一样“看不出溯源结果”。
- 针对目标路口（例如奥体西路与经十路西向东直行进口道）必须呈现“目标路口 → 直接下游路口”的十字拓扑：经十路方向、奥体西路南北方向等一跳下游节点都要在地图上可见，问题转向链高亮。
- 下钻到 zoom18 后，地图主视图必须展示渠化车道面，并在车道/进口上展示真实指标，严格参考 `references/frontend-v2/src/lib/channelizationGeometry.ts` 与 `channelizationAmap.ts`。

## 约束

- 前端禁止合成坐标、几何、指标；只消费后端真实 `path`、`lane_info`、`lane_num`、`share_pct`、饱和度、排队、绿灯利用率等字段。
- 渠化车道面可由真实 link 几何、lane_info、lane_num 按参考项目几何算法派生，这是参考项目标准做法，不属于造数。
- 数据缺失时必须 `available:false` 或不绘制，不用假数据兜底。
- 参考项目只读，不直接 import；在当前项目中沉淀同等逻辑。

## 功能需求

- FR-1 后端公开 `diagnosis.map_scenes.channelization_map`：合并 PG `channelization` 与 `trace_geometry`，只保留有真实 link geometry 的 link，并附带真实相邻路口、车道、指标字段。
- FR-2 前端 `lane` 场景在 zoom18 绘制渠化：路口 halo、道路面、进口/出口车道面、分隔线、停止线、人行横道、转向箭头、指标色带与标签。
- FR-3 前端 `trace/corridor` 场景叠加下游十字拓扑：从 `channelization_map.links` 的全部出口 link 抽取一跳下游节点，问题转向下游节点由 `downstream_trace_map.turn_traces` 高亮。
- FR-4 流量溯源继续使用需求8迁移的 `TraceLayer`，保持标准发光双层干线、沿线粒子、占比缩放节点和占比标签。
- FR-5 所有新增纯函数有单测：渠化车道解析/臂聚合/角度、下游拓扑抽取、后端渠化场景构造。

## 验收标准

- AC-1 溯源幕可清晰看到上游/下游发光链、流动粒子、占比节点与标签。
- AC-2 目标路口周边直接下游路口以拓扑节点和 link 边呈现，问题转向下游链高亮，非问题出口链弱化但可见。
- AC-3 zoom18 下钻后显示渠化车道和指标贴片，车道功能配色/箭头/LOD 与 `frontend-v2` 逻辑一致。
- AC-4 后端无真实渠化几何时前端不画渠化，返回 `available:false`。
- AC-5 前端单测与 build 通过，后端相关单测通过。
