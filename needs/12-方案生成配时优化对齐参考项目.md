# 方案生成配时优化对齐参考项目

## 背景

对比参考项目 `references/traffic_signal_deepagent`（仅借鉴逻辑，禁止 import/提交），当前项目「方案生成」阶段的诊断与策略质量已基本对齐，但**配时（方案）结果严重退化**，无法达到可信、可落地水平。

以路口「经十路与转山西路路口」实测（`frontend/src/mock/run_1_fixture.json`，trace=043a079385bd474b）：

- PG 现状配时真实可用：`current_cycle_s=130`，阶段 西直/东直=60、东左/西左=12、南直=49，`min_green_detail=35/12/35`；`raw.turn_flow`(6)、`turn_saturation`(6)、`green_utilization`(6)、`lane_detail`(50)、`lane_capacity`(5000) 均已从 PG 取到。
- 但三个候选方案配时全部塌缩为 `cycle=42`、三阶段各 `14s`、`split=0.333`、`phase_saturation=None`、无优化元数据（`meta=None`）。

## 根因（详见 `bugs/`，本需求需同步补记）

方案配时链路把「真实需求」丢失，优化器只能塌缩到最小绿：

1. `app/optimization/request_builder.py::_build_phase_plan` 对每个阶段用占位流量 `turnFlowTotal ... or 500`、车道数 `or 2`，且每阶段仅生成**单个** `phaseDirInfoDTOList` 条目（多转向合并阶段如「西直、东直」只取其一）。真实 `raw.turn_flow` / `turn_saturation` / 车道数从未绑定进相位。
2. 现状最小绿（35/12/35）、现状绿（60/12/49）未透传，优化引擎回落默认 14s。
3. 优化器输出未回填逐相位饱和度与强度元数据（参考项目输出含 `phaseSaturation` / `direction_intensity_list` / `solver`）。
4. 退化结果未被护栏识别为「不可用」，占位方案被当作成功方案返回（违反 `docs/rule.md` 14/16）。
5. 次要：`plan.recommended_plan_id`（顶层）与 `plan.recommendation.recommended_plan_id` 层级不一致，前端可能取不到推荐方案。

## 目标水平（对齐参考项目口径）

参考项目配时来自确定性供需强度优化（真实转向流量 + 现状配时 + 逐转向饱和度 + 逐阶段最小绿），输出可信的周期/绿信比/逐相位饱和度/强度偏差元数据。当前项目需达到同等可信度与可落地性。

## 后端需补齐

1. **真实流量绑定**：新增确定性绑定逻辑，将 `raw.turn_flow`（按目标时段 `step_index` 聚合的 `turn_flow_total`、`avg_lane_flow_5min`、`lane_count`）与 `raw.turn_saturation`，按 (link_id/dir8, turn_dir_no) 绑定到每个相位阶段的释放转向。数据源须来自 PG/注入 task，禁止占位常数。
2. **多转向阶段展开**：一个阶段的 `phaseDirInfoDTOList` 须包含该阶段全部释放转向（复用 `_release_movements_by_stage` 的 stage→movements 映射），而非只取一个方向。
3. **真实约束透传**：把现状 `greenTime`、`minGreenTime`（PG `min_green_detail`）、`maxGreenTime`、车道数、饱和流量（车道级）传入优化请求，去除 `or 500 / or 2 / or 15` 静默占位。
4. **优化输出增强**：优化器结果回填每阶段 `phase_saturation`（或强度）与顶层 `meta`（solver、`direction_intensity_list`、备注），供前端展示与审计。
5. **退化护栏**：当优化返回缺失饱和度/元数据、或周期显著低于现状最小可行周期（如所有阶段=默认最小绿且 cycle≈stage×min）时，判定为退化，返回 `available=false` + `reason`，不得把占位方案当成功返回。
6. **推荐字段一致**：统一 `plan.recommended_plan_id` 与 `plan.recommendation.recommended_plan_id`，保证前端稳定取到推荐方案。
7. **数据不足降级**：目标时段无真实转向流量、或流量无法绑定到任一相位时，返回结构化 `available=false + reason`，禁止编造阶段或配时参数（`docs/rule.md` 14/15/16）。

## 验收标准

1. 对「经十路与转山西路路口」晚高峰真实 PG 端到端跑通，推荐方案配时**不再塌缩**：周期落在现状最小可行周期以上、各阶段绿灯不低于真实最小绿，且带逐相位饱和度与优化元数据。
2. 制造「无目标时段流量」场景时，方案阶段返回 `available=false + reason`，护栏拦截退化输出。
3. `plan.recommended_plan_id` 前端可稳定取到。
4. 新增/更新单元测试覆盖：流量绑定、多转向展开、约束透传、退化护栏、推荐字段一致；全部通过。
5. 重采 `frontend/src/mock/run_1_fixture.json`，前端相位配时图展示可信配时（非 14/14/14 占位）。

## 前端当前处理

前端仅在 `cycle_s` 与 `phase_stage_timing_list` 同时存在时绘制相位配时图；本需求不改变前端渲染契约，仅让后端产出真实可信配时与 `available/reason` 降级标识。
