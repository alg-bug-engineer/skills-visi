# 方案生成生产级证据面板前后端联动

## 背景

需求 12 已把方案生成从占位配时推进到真实 PG 数据驱动的优化结果：推荐方案已具备 `cycle_s=98`、阶段绿灯、逐相位饱和度、`timing.meta.direction_intensity_list`、求解器备注等字段。

但当前前端仍只展示线性相位条、治理建议、风险和回滚条件，尚未达到参考项目 `references/traffic_signal_deepagent` 方案生成阶段的生产级呈现水准。参考项目的核心价值不是“截图样式”，而是将现状方案、优化方案、阶段释放方向、供需强度和求解审计信息放在同一张可核验面板中，形成专家可判断、可复核、可追责的方案证据链。

本需求明确：**禁止 mock 补洞**。所有用于前端展示的字段必须来自后端真实数据链路。`VITE_MOCK=1` 只允许回放由后端真实运行重采得到的 `frontend/src/mock/run_1_fixture.json`，不得在前端手工编造周期、阶段、方向、强度或审计字段。

## 当前差距

### 数据契约差距

当前 `frontend/src/mock/run_1_fixture.json` 中，方案配时已包含可信优化结果，但缺少生产展示所需的完整对照契约：

- `plan.candidates[].timing.current_cycle_s` 为空，无法展示“现状周期 → 优化周期”。
- `phase_stage_timing_list[]` 缺少现状阶段时长/现状绿灯结构，无法展示“旧秒数 → 新秒数”和阶段 delta。
- `phase_stage_timing_list[]` 缺少结构化释放方向，如 `phaseDirInfoDTOList`、标准化 `movement_keys` 或 `movements`，前端只能从阶段名猜测方向，不能作为生产证据。
- `timing.meta.direction_intensity_list` 已存在，但前端类型未建模、组件未渲染，供需强度证据沉在 raw JSON 中。
- 数据质量、来源、降级原因、虚拟流量说明没有统一前端展示契约，专家无法一眼区分“真实 PG 值”“推算虚拟流量”“数据不足降级”。

### 前端呈现差距

当前 `PlanDrawer.vue` 仍是治理建议抽屉：

- 左侧展示 `PhaseDiagram.vue` 线性相位条，不是阶段形式卡片。
- 没有周期优化对比横幅。
- 没有每阶段现状/优化/差值对比。
- 没有相位释放方向小图。
- 没有各方向供需强度 `I_dir` 与目标强度 `I_obj` 的分布条。
- 没有将求解器、目标函数、数据源、护栏通过/降级原因作为审计信息展示。

## 目标

让方案生成阶段达到生产可用水准：后端输出真实、完整、可审计的方案证据契约；前端在 `VITE_MOCK=1` 回放真实采集 fixture 时，能呈现接近参考项目截图的信息密度和可信度，包括：

1. 周期优化对比：现状周期、优化周期、周期差值。
2. 阶段形式：每阶段展示现状阶段时长/优化阶段时长/差值、现状绿灯/优化绿灯/最小绿、阶段释放方向小图。
3. 供需强度：展示 `I_dir` 列表、目标强度 `I_obj`、超目标风险标记、虚拟流量说明。
4. 审计说明：展示数据源、优化器、求解器、护栏状态、降级原因、关键 notes。
5. 禁止前端造数：字段缺失时显示“后端未返回可审计证据”，不得用阶段名、默认周期或硬编码方向补假数据。


字段命名可在开发时根据现有代码微调，但必须满足以下语义：

- 前端能直接读取现状周期和优化周期，不计算或猜测现状周期。
- 前端能直接读取每阶段现状时长、优化时长和释放方向，不从 `phase_stage_name` 反推。
- `direction_intensity_list` 必须保留 `dir8No`、`turnDirNo`、`label`、`intensity`，并补齐流量来源或虚拟流量标记。
- 数据不足时返回结构化 `available=false`、`reason`、`missing_fields`，不得输出看似成功的空证据。

### 2. 真实数据来源

后端必须从真实链路补齐字段：

- 现状周期和现状阶段配时来自 PG signal plan。
- 释放方向来自阶段与转向绑定结果，优先复用 `phaseDirInfoDTOList` 或 `_release_movements_by_stage` 的真实映射。
- 转向流量和饱和度来自 PG `turn_flow`、`turn_saturation`、车道数据。
- 虚拟流量只能由优化器或后端显式计算并标注，不能由前端编造。

### 3. 降级与护栏

后端需在以下情况阻断生产式展示：

- 无 `current_cycle_s` 或阶段现状配时。
- 无任何可绑定释放方向。
- 无 `direction_intensity_list` 或所有强度为空。
- 优化器退化、占位、缺少逐相位饱和度。

返回结构：

```json
{
  "available": false,
  "reason": "方案证据缺少现状阶段配时，无法展示生产级优化对比",
  "missing_fields": ["timing.current_cycle_s", "phase_stage_timing_list[].current_timing"]
}
```

## 前端改造需求

### 1. 类型契约

扩展 `frontend/src/api/types.ts`：

- `PlanTimingEvidence`
- `PhaseStageTimingEvidence`
- `StageMovement`
- `OptimizationMeta`
- `DirectionIntensity`
- `PlanEvidenceQuality`

所有新增字段均可空，但组件必须按“缺失即降级提示”处理，不能填默认假值。

### 2. 组件结构

新增组件：

- `frontend/src/panels/PlanEvidencePanel.vue`：方案证据总容器。
- `frontend/src/viz/StageCards.vue`：阶段形式卡片区。
- `frontend/src/viz/StageMovementCanvas.vue`：按结构化 movements 绘制阶段释放方向。
- `frontend/src/viz/DirectionIntensityPanel.vue`：各方向供需强度条。
- `frontend/src/viz/OptimizationAuditPanel.vue`：优化器、数据源、notes、降级原因。

调整：

- `PlanDrawer.vue` 保留接受/退回、推荐理由、执行策略、红线等决策操作。
- 将现有 `PhaseDiagram.vue` 作为备用视图或降级视图，不再作为生产级方案主视图。

### 3. 展示规则

- 有完整证据时展示：周期对比横幅 + 阶段卡片 + 供需强度 + 审计说明。
- 缺少现状配时时：不展示“现状 vs 优化”，显示后端缺失原因。
- 缺少 movements 时：不画阶段方向图，显示“后端未返回释放方向证据”。
- 缺少 `direction_intensity_list` 时：不展示强度条，显示“后端未返回供需强度证据”。
- `I_dir > I_obj` 用风险色标注，`I_dir <= I_obj` 用通过色标注。
- 虚拟流量方向必须显示“虚拟流量/推算”标记。

## 回放与调试要求

`VITE_MOCK=1` 的唯一用途是回放真实后端产物：

1. 完成后端改造。
2. 运行后端真实接口，连 PG 或真实注入数据。
3. 用 `python scripts/capture_frontend_mock.py --live` 重采 `frontend/src/mock/run_1_fixture.json`。
4. 校验 fixture 中包含生产证据字段。
5. 再启动前端 `VITE_MOCK=1 npm run dev`，用该 fixture 离线调试 UI。

禁止：

- 前端手写 fixture 字段补齐。
- 在 `run_1_fixture.json` 中手工补周期、阶段、方向、强度。
- 组件从阶段名猜测正式生产方向图。
- 无真实数据时仍展示完整优化对比。

## 验收标准

1. 后端真实运行产出的 `run_1_fixture.json` 包含 `current_cycle_s`、阶段 `current_timing`、结构化 `movements`、`direction_intensity_list`、`meta.data_quality`。
2. 前端 `VITE_MOCK=1` 回放该 fixture 时，方案抽屉能展示周期对比、阶段形式、方向图、供需强度和审计说明。
3. 人为移除关键字段时，前端显示降级提示，不补假数据。
4. 后端测试覆盖证据契约、真实字段透传、缺字段降级。
5. 前端单测覆盖完整证据展示、缺字段降级、强度超目标风险色。
6. 前端 e2e 覆盖从输入到方案抽屉可见，且能看到周期对比、阶段卡、供需强度、审计信息。
7. `npm run build`、`npm run test`、关键 pytest 全部通过。
