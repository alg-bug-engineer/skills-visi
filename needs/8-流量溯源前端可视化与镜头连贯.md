# 需求8 · 流量溯源前端可视化与镜头连贯运镜

## 背景

需求7 已在后端补全真实几何（分支 `feature/frontend-presentation-optimization` 提交 `672859c`）：
`diagnosis.flow_trace.entry_traces[]` 携带真实 `path`/`upstream_lng/lat`/`upstream_movements[].share_pct`；
`diagnosis.map_scenes.downstream_trace_map.turn_traces[]` 携带真实 `path`/`lon/lat`/`share_pct`/`capacity`。

但前端呈现（`frontend/src/map/MapController.ts`）仍是简化版：
- 溯源发光走线渲染逻辑与参考项目 `references/流量溯源`（= `references/frontend-v2`）**不一致**：缺发光双层干线随占比变宽、粒子随路径长度定速、节点按 `coverage` 缩放脉冲、上游琥珀/下游青蓝分色、可点开占比标签等。
- **地图严重闪烁**：从城市视角下钻路口、再进入车道级时，镜头出现「先缩小再放大」的跳变；流式 `diagnosis` 到达时 `applyScene` 被二次触发，覆盖物 `clear()` 后重绘造成闪现；抬升到干线视角是直接刷新而非连贯过渡。

## 约束（docs/rule.md）

- 约束19：前端只做呈现，**禁止合成/伪造**几何/坐标/指标。缺字段 → 改后端接口 + 重采 `frontend/src/mock/*_fixture.json`；取不到真实数据 `available:false` 降级「暂无数据」。
- 用户要求：**严格符合参考项目 `references/流量溯源` 的可视化逻辑与取数逻辑，仅允许修改配色**；深度吸收 `references/frontend-v2` 的地图动作、演示、镜头运镜。

## 目标

1. 前端溯源可视化层与参考项目 `UpstreamTraceLayer` 呈现逻辑一致（发光双层干线 + 沿线粒子 + 占比缩放脉冲节点 + 分色 + 占比标签），仅配色对齐本项目主题。
2. 消除地图闪烁：城市→路口→车道 **单调连贯下钻（15→18 无回退跳变）**；抬升到干线视角 **从 18 平滑连贯过渡到 17**，禁止直接刷新。
3. 取数逻辑符合参考项目：几何定方向（entrance=来向上游、exit=去向下游），占比来自真实 `share_pct`，无占比时显示「拓扑」而非编造。
4. mock（`VITE_MOCK=1`）与真实后端一致；若后端缺前端渲染所需字段则补后端 + 重采 fixture。

## 功能需求

- FR-1 移植参考 `traceParticles`（`interpolatePath`/`sampleAlongPath`/`approxPathLength`/`particleDurationFor`）为纯函数工具，替换 `MapController` 内联 `lerpPath`。
- FR-2 移植参考溯源渲染层：`revealEdge`（外层 glow + 亮核 + `showDir` + 沿线粒子）、`revealNode`（按 `coverage` 缩放尺寸/透明度/发光的脉冲节点，目标红/上游琥珀/下游青蓝/治理绿）、`renderDownstreamTraces`（去向青蓝单链 + 节点 + 占比标签）、上游节点占比标签（`coverageNodeStyle`/`buildCorrelateLabelHtml` 口径）。仅在 `path.length>=2` 时渲染。
- FR-3 溯源幕（`trace`/`corridor`）用 FR-2 渲染 `entry_traces`（上游琥珀）与 `turn_traces`（下游青蓝），占比缺失显示「拓扑」，坐标缺失不产节点。
- FR-4 镜头连贯：新增连贯运镜工具，`drillToIntersection` 每步 `zoom` 对 **当前 zoom 取 max（单调不回退）**，避免「先缩小再放大」；车道级续接当前镜头平滑放大到 18。
- FR-5 干线抬升：溯源/干线幕镜头从当前（≈18）**单次平滑 `flyTo` 过渡到 17**（允许受控降 zoom + 动画），不得直接 `setZoomAndCenter` 硬切。
- FR-6 去抖再入：`AMapProvider` 消除「currentAct 与 diagnosis 双 watch 各调一次 `applyScene`」造成的镜头/覆盖物重置闪烁；同一幕数据补齐时仅补绘覆盖物、不重放镜头。
- FR-7 覆盖物切换不闪：镜头到位后再绘制该幕覆盖物；换幕时对旧覆盖物做淡出/差量，不做「先清空后重绘」的硬闪。
- FR-8 用户手动干预（拖拽/缩放）后，后续系统步骤不强拉视角（对齐参考 `userInteracted`）。

## 非功能需求

- NFR-1 纯函数（插值/采样/步进 zoom 计算）含单测。
- NFR-2 仅改配色，呈现与取数逻辑对齐参考项目；不新增前端造数。
- NFR-3 兼容既有九幕、流式门控、`VITE_MOCK=1` 回放。
- NFR-4 当前分支开发，人工确认前不合入 main。

## 验收标准

- AC-1 溯源幕上游走线为琥珀发光双层干线 + 沿线流动粒子 + 按 71.6% 占比放大的脉冲节点 + 可读占比标签；下游为青蓝单链，无占比节点显示「拓扑」。
- AC-2 城市→路口→车道全程镜头单调放大（15→18），无「先缩小再放大」闪烁；肉眼/截图确认无跳变。
- AC-3 干线幕镜头从 18 平滑过渡到 17（单次动画 ≥800ms），无硬刷新。
- AC-4 流式 `diagnosis` 到达时不再触发镜头重放/覆盖物硬闪。
- AC-5 `VITE_MOCK=1` 与真实后端呈现一致；如补后端字段则 `capture_frontend_mock.py` 重采后 fixture 同步。
- AC-6 前端单测通过、`tsc` 构建通过。
