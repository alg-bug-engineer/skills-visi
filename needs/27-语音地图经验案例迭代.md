## 背景

当前演示闭环在语音播报、地图动作、经验吸收可视化、案例相似度呈现上已有基础能力（需求 26 语音模板、需求 7–9 流量溯源地图、需求 14 经验吸收、需求 24 沉淀面板），但面向领导汇报与产品叙事仍缺以下**五类**增强，需作为下一轮迭代统一规划。

## R1 · 语音播报新增路口认知信息

### 目标

进入诊断/定位阶段时，语音除现有「目的 + 方法 + 结论」外，增加**路口空间认知**播报，帮助听众建立地理方位感：

> 「{路口名} 路口，东西向是 {东西向道路名}，南北向是 {南北向道路名}。」

### 要点

- 数据来源：`spatial_scene` / 路口加载接口中的道路名称与方向属性，禁止前端编造。
- 插入时机：建议在 **act2_locate（诊断对象定位）** 或 act1 结论后首句，与地图镜头落到目标路口同步。
- 配置：`voiceTemplates.ts` 新增认知槽位；`voiceSlotFillers.ts` 从 `RunResponse` 填充 `{intersection_name}`、`{ew_road}`、`{ns_road}`。
- 降级：若某方向道路名缺失，跳过该半句或改为「东西向道路信息待补全」，不读空字符串。

### 验收（规划）

- [x] 进入定位步骤时 TTS 含路口名 + 东西/南北向道路名
- [x] 与地图定位动作、旁白文案一致
- [x] 单测覆盖槽位填充与缺失降级

## R2 · 丰富细化地图动作（全链路配套）

### 目标

处置闭环各阶段（诊断 → 成因 → 策略 → 方案）均应有**与叙事同步的地图动作**，避免「面板在讲、地图不动」或仅 act5 有溯源动画而其他幕退化为单点脉冲。

### 分阶段期望动作（草案）

| 阶段 | 地图动作方向 |
|------|----------------|
| 诊断（act3–4） | 高亮问题进口道/排队方向；本路口 vs 下游对比（双节点高亮、指标气泡） |
| 成因（act6） | 标注主因关联的空间对象（进口道、相位、下游节点）；案例相似路口在地图上轻量标记 |
| 策略（act7） | 策略作用范围可视化（协调路段、保护下游范围、约束红线区域） |
| 方案（act8） | 配时变化预览（相位绿信比变化、协调相位连线）；与 PlanDrawer 联动 |

### 要点

- 动作定义需与 `useTimeline` / act 状态机绑定，进入 act 即触发，离开 act 可保留残影或淡出。
- 复用现有 MapLibre 图层能力（溯源走廊、渠化、下游拓扑），按阶段组合而非每幕重写。
- 遵循 `docs/rule.md`：几何与指标来自后端真源，前端只做呈现编排。

### 验收（规划）

- [x] 诊断/成因/策略/方案四段均有可辨识、与旁白同步的地图动作
- [x] 动作不阻塞 SSE 与步骤推进；`prefers-reduced-motion` 可降级为静态高亮
- [ ] 与需求 8/9 镜头连贯性不回归（需联调目视确认）

## R3 · 经验吸收体现「有经验 vs 无经验」对比

### 目标

经验吸收不应仅是固化前的动画流程，而要让观众**看见经验带来的差异**：同样场景下，有历史经验/案例支撑 vs 无经验时的诊断路径、策略选择或方案质量对比。

### 呈现方向

1. **吸收阶段**：在现有 6 阶段（recap→…→blueprint）中增加「对照」子屏或 chips，展示：
   - 无经验：仅依赖实时指标时的结论/策略草案（或标注「未命中经验」）
   - 有经验：命中经验/案例后的修正项（策略调整、护栏提示、配时偏好等）
2. **闭环内引用**：右侧卡片「参考依据」跳转沉淀面板时，可侧栏对比「若未引用该经验则…」
3. **价值量化**（可选）：沿用需求 14 价值对照表，扩展为 before/after 可扫读条目，而非仅文字动画

### 要点

- 对比内容必须来自本轮真实检索与 pipeline 输出，禁止编造「假对比」。
- 与 `needs/24` 沉淀面板全量历史呈现分工：R3 侧重**本轮推演内的吸收价值叙事**，24 侧重**历史资产库**。

### 验收（规划）

- [x] 固化/吸收流程中可见「无经验基线 vs 吸收后」至少 1 组可理解对照
- [x] 对照项可追溯到具体经验/案例 ID 或标签
- [ ] 领导演示场景下 30 秒内能讲清「经验帮了什么」（需演示确认）

## R4 · 案例相似度细化与案例体系呈现

### 目标

相似案例不应只展示「相似度 0.91 + 标题」，需回答：**为什么相似、相似在哪几个维度、对本路口治理有什么可迁移帮助**；并推进案例体系分层细化。

### 呈现方向

1. **相似理由结构化**：扩展 `similarity_points` 展示为可读标签组，例如：
   - 场景：同路口类型 / 同时段 / 同问题形态
   - 指标：排队比、饱和度、下游承接等匹配点
   - 措施：历史采取的策略动作是否可复用
2. **帮助说明**：每条案例增加「可借鉴点 / 不可直接套用点」短句（后端 LLM 或规则生成，需标注来源）。
3. **案例体系分层**（与需求 24 对齐）：
   - **行业案例**（教科书/专家知识）
   - **路口沉淀案例**（用户确认下发）
   - **高度相似 / 一般相似** 分级与代表案例选取逻辑透明化（为何 carousel 只展示 N 条）
4. **交互**：CauseCard 编号点击 → 详情含相似维度 + 帮助 + 跳转沉淀面板完整条目

### 要点

- 后端 `CaseLibraryService.search_similar` 契约可扩展 `similarity_dimensions`、`transferable_actions`、`caveats` 等字段。
- 前端 `CauseCard` / 案例 carousel 以结构化区块呈现，避免长段落堆砌。

### 验收（规划）

- [x] 每条代表案例可见 ≥2 条「为何相似」要点
- [x] 可见「对本场景的帮助」一句话摘要
- [x] 案例分级（高相似/匹配数）与展示条数逻辑有 UI 说明或 tooltip
- [ ] 与沉淀面板路口案例条目可双向定位

## R5 · 流量溯源与亚楠对接：轨迹信息可行性

> **结论（2026-07-10）：亚楠侧确认暂无车辆/路径级轨迹数据，本需求忽略，保留 link-sniff 统计溯源不回归。**

### 背景

- 会议确认（`docs/20260702-交通智能体沟通-神思-办公室.md`）：**亚楠**负责下游流量溯源，已确认 PG 侧**存在流量去向溯源**能力。
- 当前项目已接入：
  - `dws_tfc_inter_turn_flow_correlate_m`（`flow_correlate`）：进口道+转向 → 关联路口占比 + `trace_type`（来向/去向）
  - `trace_geometry`：宽表 ⋈ `dim_link_info.geom` 的进/出口 link 折线 + 邻接路口中心
  - 地图呈现：`flow_trace_links_sniff_map` 多跳走廊 + link 十字 + 占比标签（需求 7/9/23）
- **缺口**：现有溯源是「统计占比 + link 几何走廊」，**尚无车辆/路径级轨迹**（如浮动车轨迹、OD 路径序列、逐段行驶 polyline）。能否叠加轨迹信息，需与亚楠侧数据口径对齐后评估。

### 目标（待对接确认）

1. **数据对接**：与亚楠确认轨迹/路径类数据的来源表或接口、字段契约、覆盖范围（路口/时段/转向粒度）。
2. **可行性评估**：明确「轨迹信息」在本项目中的具体含义（见下）及能否与现有 `flow_correlate` 关联呈现。
3. **若可行**：定义后端取数 + 前端地图层扩展方案，与现有 link-sniff 场景并存、可降级。

### 「轨迹信息」待澄清口径（对接清单）

| 可能含义 | 说明 | 与现状关系 |
|----------|------|------------|
| **车辆浮动车轨迹** | 单车/样本车辆经过路口间的实际 GPS/卡口轨迹 polyline | 新增图层，需独立数据源 |
| **OD 路径链** | 目标路口某转向 → 下游多跳路径序列（非仅一跳占比） | 可视为 `flow_correlate` 多跳扩展 |
| **link 级行驶方向轨迹** | 在已有 link geom 上叠加流量权重/方向动画 | 与 `trace_geometry` 最近，改造成本较低 |
| **trace 字段扩展** | correlate 表或 companion 表增加 path_id / geom_wkt 等 | 需亚楠确认是否已在数仓落地 |

### 对接事项（与亚楠）

- [ ] 轨迹数据表名 / API、主键与 `inter_id` / `f_dir8_no` / `turn_dir_no` / `period_type` 对齐方式
- [ ] 来向溯源 vs 去向溯源是否均有轨迹；与 `trace_type=UPSTREAM/DOWNSTREAM` 映射关系
- [ ] 时段、日类型、样本期与当前 `flow_correlate` 单日样本期（`ticket_nlu_schema` TODO）是否一致
- [ ] 演示路口（解放东路×奥体中路、奥体西路×经十路等）覆盖情况与缺失降级策略
- [ ] 数据量级与查询 SLA（是否可并入 `iter_checklist_load` 或需异步预聚合）
- [ ] 合规/脱敏要求（若含单车轨迹）

### 呈现方向（若数据可用）

- 地图：在 act5 溯源幕叠加**可选轨迹图层**（如半透明路径线 / 样本轨迹束），与现有 link 走廊、占比标签分层开关。
- 面板：CorridorCard 增加「轨迹支撑」说明（样本量、路径代表度），禁止无数据时编造轨迹。
- 旁白/语音：可补充「主要车流沿 xx 路径去往下游 xx 路口」（需真实统计支撑）。

### 约束

- 遵循 `docs/rule.md` 约束 19：轨迹几何必须来自 PG/亚楠侧真源，前端禁止合成 polyline。
- 无轨迹数据时 `available:false` + `reason`，保留现有 link-sniff 溯源不回归。
- 不对接完成前**不开发**，本条目仅记录需求与对接清单。

### 验收（规划）

- [ ] 与亚楠完成口径对齐纪要（轨迹定义、表/接口、覆盖范围）
- [ ] 输出 feasibility 结论：做 / 不做 / 分阶段做
- [ ] 若做：后端契约草案 + 1 个演示路口 live 样例 + 地图降级单测
- [ ] 与需求 23 多跳走廊呈现兼容，不破坏现有 `renderSniffScene` 契约
