# 配时方案优化与时段解析

## 背景

对齐参考项目 `references/traffic_signal_deepagent` 的方案生成呈现与时段驱动逻辑后，当前项目在以下三方面仍有差距：

1. **阶段形式**：卡片信息密度与参考项目不一致，绿灯变化不够突出，缺少「阶段形式」区块语义。
2. **供需强度**：需求 20 增加了虚拟流量口径说明，但用户反馈应去除「虚拟流量」标签与脚注，仅展示 I_dir 与 I_obj 对比。
3. **时段解析**：用户常以「早高峰 / 晚高峰 / 07:00-09:00」表达，当前 `request_builder` 仅透传 `ticket.time_range`，未与 PG `schedule_cfg` 映射到正确的 `period_plan_no` 与流量窗口，导致配时可能基于错误日计划方案或错误时段流量。

## 目标

1. 方案证据面板「阶段形式」对齐参考项目：周期横幅 + 每阶段现状/优化绿灯与阶段时长对比，释放方向图保留。
2. 「各方向供需强度」仅展示转向、强度条、I_dir 数值与 I_obj 目标线；**不再展示**「虚拟流量」标签、`has_virtual_flow` 脚注及 `historyVirtualFlowVph` 相关 UI。
3. 新增确定性时段解析：从 `diagnosis_ticket.period` / `time_range` 解析 `target_periods`、`period_plan_no`、5min `step_index` 窗口，并在方案生成前切换至对应日计划方案与时段流量。

## 后端需求

### 时段解析（`app/data/schedule_period_resolver.py`）

- 输入：`ticket`、`schedule_cfg` 行、`day_of_week`。
- 输出：
  - `target_periods: ["HH:MM-HH:MM"]`
  - `period_plan_no`
  - `period_label`（标准中文或时段 key）
  - `step_index` / `step_index_end`
  - `match_method`（`explicit_time_range` | `peak_label` | `schedule_overlap` | `fallback`）
- 规则：
  - 显式 `time_range`（如 `17:30-18:30`）优先；
  - `早高峰/晚高峰/平峰` 用语义 + `ticket_nlu_schema.hour_ranges` 与 schedule 时段最大重叠匹配；
  - 无法匹配时降级并记录 `reason`，禁止静默使用错误 plan。

### 方案生成链路

- 方案生成前调用 `prepare_signal_for_ticket()`：按解析结果重建 `signal`（正确 `plan_no` + 阶段列表）并重绑该时段 `turn_flow`。
- `build_optimizer_request` 使用解析后的 `target_periods`、`planNo`、`obj_intensity`。
- `timing.meta` 增加 `target_periods`、`period_plan_no`、`period_match_method`。
- `_build_optimization_meta` 不再输出 `data_quality.has_virtual_flow` / `virtual_flow_movements`；`direction_intensity_list` 条目去除 `historyVirtualFlowVph` 字段。

## 前端需求

- `StageCards.vue`：增加「阶段形式」标题区；卡片以「现状绿 → 优化绿 (+Δ)」为主视觉，阶段总时长为辅。
- `PlanEvidencePanel.vue`：横幅展示当前优化时段（来自 `timing.meta.target_periods`）。
- `DirectionIntensityPanel.vue`：删除虚拟流量 tag、脚注及「含虚拟流量兜底」文案。

## 验收标准

1. 用户输入「晚高峰」或 `17:30-18:30` 时，优化请求 `target_periods` 与 PG schedule 中对应时段一致，`signal.plan_no` 为 schedule 映射的 `period_plan_no`。
2. 前端方案抽屉展示优化后的阶段形式，无「虚拟流量」相关 UI 文案。
3. `timing.meta.direction_intensity_list` 无 `historyVirtualFlowVph`，`data_quality` 无虚拟流量字段。
4. 新增 `tests/test_schedule_period_resolver.py`；更新 `plan-evidence` / `test_plan_movement_labels` 单测；pytest 与前端 vitest 通过。
