# 需求11 · 治理建议配时/协调后端补齐与前端技术债清理

> 来源：`docs/项目进度.md` 待办 P0（需求10 后端补齐）+ P1（前端技术债清理）合并立项。
> 约束基线：`docs/rule.md`（尤其 14 禁 demo、16 数据真源、18 先写计划、19 前端禁造数）。

## 背景

需求10 前端已就绪：仅在字段齐全时绘制相位配时图；协调图在缺节点间距与绝对相位时持续显示「暂不绘制协调图」。当前后端：

- 配时明细（`plan.candidates[].timing.cycle_s` + `phase_stage_timing_list`）链路完整、有真实 PG 来源，缺信号时已按 `available/reason` 降级——本需求仅补测试与口径校验。
- 干线协调（`diagnosis.arterial_analysis`）字段不足：`phase_offset_match` 为占位串 `"pg"`，缺节点间距、绝对相位/相位差、行程速度/旅行时间、协调方向与数据来源，导致前端无法绘制协调图。

同时 `PlanDrawer` 改版遗留死代码与一处违反约束19（客户端合成数据）的 `TimeSpaceDiagram.vue`，以及离线 mock fixture 缺真实相邻路口指标，需一并清理。

## P0 · 后端补齐（阻塞治理建议真实呈现）

### 需求10-1 配时方案明细（校验 + 测试）
- 每个推荐/候选方案返回 `cycle_s` 与 `phase_stage_timing_list`，来自真实现状配时或优化器结果。
- 信号缺失（无 `task.signal`、无 PG、`allow_demo_fallback=false`）时返回 `available=false` + `reason` + `source`，禁止 mock/demo 进入生产响应。
- 补充回归测试固化上述两条口径。

### 需求10-2 干线协调图数据（新增）
后端在诊断输出中新增结构化协调数据块 `diagnosis.coordination`，字段全部来自真实数据源，缺失即降级：

- 节点列表 `nodes[]`：上游 → 目标 → 下游，含 `inter_id/inter_name/lng/lat/role`。
- 节点间距 `spacing_m` + `spacing_source`（真实来源 `dim_link_info.length_m`，经 `scope.adjacent_inter_spacing_detail`）。
- 绝对相位 `offset_abs_s` + `offset_source`（目标取 `signal.offset_s`；相邻路口取相邻路口现状配时 `offset_sec`）。
- 相位差 `phase_diff_s`：相邻与目标绝对相位之差（按周期取模），两端相位均可用时才计算。
- 行程速度/旅行时间 `travel_speed_kmh` / `travel_time_s` + `travel_source`（速度取真实 `link_speed`/`line_index`；旅行时间由 `间距/速度` 计算）。
- 协调方向 `direction`（`inbound`/`outbound`/`bidirectional`，由主导来向/去向流量判定）。
- 数据来源 `source` 汇总标注（如 `pg_signal+link_geom+line_index`），禁止演示/mock 口径。

### 需求10-3 可用性标识（新增）
- `coordination.available=false` + `reason` 明确缺失原因（如 `缺少相邻路口绝对相位`、`缺少路段速度`、`缺少节点间距`）。
- 可用性门控：`nodes>=2` 且（相位差可算 或 行程时间可算）时 `available=true`；否则 `false`。
- 保留并复用现有 `arterial_analysis` 字段，占位串 `phase_offset_match="pg"` 替换为真实相位关系或明确降级值。

## P1 · 前端技术债清理

### 需求11-4 移除死代码
- 删除 `frontend/src/stores/presentation.ts` 中 `PlanTab` 类型、`State.planTab`、`state()` 初值、`setPlanTab` action、`reset()` 复位赋值（共 5 处，全仓无引用）。
- 删除 `frontend/src/viz/TimeSpaceDiagram.vue`（代码零 import，仅文档提及，且违反约束19 客户端合成斜带）。
- 同步清理 `frontend/README.md`、`plans/5-前端UI九幕演示.md`、`docs/项目进度.md` 中对上述符号/组件的描述。
- 若绘制协调图，须新增仅消费后端真实 `coordination` 字段的组件（禁止客户端合成 link/节点/相位）。

### 需求11-5 重采 mock fixture
- 用带真实 `channelization_map` 与相邻路口指标（含新增 `coordination`）的数据重采 `frontend/src/mock/run_1_fixture.json`。
- 采集走 `scripts/capture_frontend_mock.py`（优先从最新 `completed=true` 真实运行日志 `--from-log`，或 `--live` 连 PG）。
- 无真实 PG 数据时 fixture 中 `coordination.available=false`，前端据此降级，严禁前端造数。

## 验收标准
- 后端 `pytest tests/ -q` 全绿，新增协调/配时口径测试通过。
- 前端 `npm run test -- --run` 与 `npm run build` 通过，删除死代码后无 TS/引用报错。
- 生产响应中协调/配时字段无 mock/demo 口径；缺数据时统一 `available=false` + `reason`。
- 前端在字段齐全时绘制真实协调图，否则显示降级提示，不出现客户端合成数据。
