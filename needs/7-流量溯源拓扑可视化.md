# 需求7 · 上下游流量溯源拓扑可视化（后端补全真实几何）

## 背景与问题

前端"流量溯源/成因"幕的地图动作退化为"目标路口一个脉冲点 + 左右面板纯文字"，根因在**数据侧缺少真实 link 几何**：

- 后端 `topology_from_pg_raw` 旧实现：上游取 `flow_correlate` 但**无坐标、无 link 折线**；下游错误地取自 `turn_perf`（那是目标路口自身的转向指标，既非下游路口，也无坐标/几何）；目标中心解析把 `geom_center`（WKT `POINT(lng lat)`，空格分隔）当成逗号分隔，导致 `target_lng/lat` 恒为 `null`。
- 于是 `flow_trace.entry_traces[].path=[]`、`downstream_trace.turn_traces[].path=[]`、节点 `lng/lat` 多为 `null`，地图无来向/去向拓扑走线。

**约束（docs/rule.md 约束19，本次新增）**：前端只做呈现，**禁止在客户端凭标量合成路网几何/坐标/指标**。前端缺数据 → 改**后端接口**补全真实数据（数据真源见约束16），再跑 `scripts/capture_frontend_mock.py` 更新前端 `VITE_MOCK=1` 调试数据。取不到真实数据时返回 `available:false`+`reason`，前端降级"暂无数据"。

真实数据源（见 `docs/路口转向流量上下游关系统计表.md` 与 PG road6 维表）：
- link 折线几何：`road6.dim_link_info.geom`（`ST_AsText` → WKT `LINESTRING`）。
- 路口中心：`road6.dim_inter_info.geom_center`（WKT `POINT`）。
- 进/出口 link 与方向：`road6.dwd_tfc_rltn_wide_inter_ft_link`（`link_role`=entrance/exit、`dir8_code`）。entrance link 的 `f_inter_id` 为上游相邻路口，exit link 的 `t_inter_id` 为下游相邻路口。
- 转向占比：`xianchang.dws_tfc_inter_turn_flow_correlate_m.flow_share_ratio`（`trace_type` UPSTREAM/DOWNSTREAM，按 `inter_id+f_dir8_no+turn_dir_no` 归一）。

## 目标

后端在 `flow_trace` / `downstream_trace` / `map_scenes` 中返回**真实几何 + 真实占比**的上下游一跳拓扑，使前端可直接用真实 `path` 渲染来向/去向发光走线与流动动作；`VITE_MOCK=1` fixture 与真实后端一致。

## 功能需求（后端）

- FR-1 新增 `_query_trace_geometry`：按目标 `inter_id` 联查宽表 + `dim_link_info`，返回每条进/出口 link 的 `geom_wkt`、`dir8_code`、`link_role`、`relation_direction`、邻接路口 `id/name/lng/lat`。
- FR-2 目标中心修正：用 WKT `POINT` 解析 `geom_center`，得到真实 `target_lng/lat`。
- FR-3 几何为方向真源：问题进口（`f_dir8_no`）的 entrance link → 上游来向节点；对应转向的 exit link（`exit_dir8_for_turn`）→ 下游去向节点；`path` 取真实 `LINESTRING`，按上游→目标 / 目标→下游定向。
- FR-4 占比为真实值：从 `flow_correlate` 按 `(trace_type, cor_inter_id)` 匹配 `flow_share_ratio` 附到对应节点；因该数据集 `trace_type` 存在经验性反转，采用"几何定方向、占比按 cor_inter_id 就近匹配（优先对应 trace_type，回退另一类型）"，避免误判来向/去向。
- FR-5 日类型回退：目标路口无请求日类型（如"周五/工作日"）的月度聚合时，回退最新月任意日类型（仍为真实聚合值），保证占比可用。
- FR-6 契约贯通：`build_flow_trace.entry_traces[].path`、`build_downstream_trace.turn_traces[].path`、`map_scene` 的 `path/lon/lat` 携带真实几何；无几何时 `available:false`+`reason`。
- FR-7 采集刷新：跑 `capture_frontend_mock.py --live` 重新生成 `frontend/src/mock/run_1_fixture.json`，含真实 `path`/坐标/占比。

## 功能需求（前端，后置）

- FR-8 前端消费真实 `path` 渲染上下游拓扑（发光折线 + 方向 + 流动粒子 + 节点/占比标签、来向琥珀/去向青、连贯运镜），**仅在 `path` 存在时渲染，禁止任何前端合成**；无 `path`/`available:false` 时降级"暂无数据"。

## 非功能需求

- NFR-1 几何解析为纯函数并含单测（WKT 解析、折线定向、topology 构建、无几何不合成）。
- NFR-2 数据真源：坐标/折线/占比全部来自 PG，禁止后端/前端合成伪造。
- NFR-3 兼容既有九幕与流式门控；`VITE_MOCK=1` 与真实后端双兼容。
- NFR-4 当前分支开发，人工确认前不合入 main。

## 验收标准

- AC-1 `topology_from_pg_raw` 对示例路口（经十路与转山西路 `011wwe289qc00001`，东向西直行）返回上游/下游节点，`path` 为真实多点 `LINESTRING`（≥5 点），`target_lng/lat` 非空。
- AC-2 上游主走廊节点携带真实 `flow_share_ratio` 占比（示例 奥体西路 ≈71.6%）。
- AC-3 无几何时不产生任何节点/路径（`geometry_source=unavailable`），不合成。
- AC-4 `capture_frontend_mock.py` 重采后 `run_1_fixture.json` 的 `flow_trace/downstream_trace/map_scenes` 含真实 `path`/坐标/占比。
- AC-5 后端单测（geometry + topology）+ 既有相关单测通过。
- AC-6（前端后置）`VITE_MOCK=1` 溯源幕用真实几何呈现来向/去向拓扑与流动动作，无前端造数。
