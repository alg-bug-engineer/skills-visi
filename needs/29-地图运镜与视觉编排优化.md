# 需求 29 · 地图运镜、特效与文字标注编排优化

> **状态：待开发**  
> 分支：`20260711160000-29-地图运镜与视觉编排优化`

## 背景

需求 8 已解决溯源发光层与单调下钻/平滑抬升的基础运镜；需求 27 R2 已为 act3–8 补齐 `diagnosis_compare` / `cause_spatial` / `plan_preview` 等 map_scenes 与 `sceneEvidencePolicy` 分层。

但面向领导演示的**主观体验**仍明显不足，集中在**诊断之后**（act3 起）：

1. **镜头**：act3→act4→act6→act7→act8 连续五幕均为 zoom 18 渠化级，pitch 微调不足以区分叙事；act4 下游对比、act7 控制范围等多节点场景未 `fitBounds`；换幕时 `clear()` 硬切，覆盖物无过渡（需求 8 FR-7 未落地）。
2. **特效**：除 act5 溯源外，其余幕仅 `pulseMarker` 圆点 + 虚线框，与 `docs/剧本.md` 描述的「进口道高亮、排队线、方向箭头、风险边界、协调范围」差距大。
3. **文字标注**：`buildMetricMarkers` 用径向偏移而非真实进口几何；`cause_spatial` 案例标记堆叠在目标路口；`plan_preview` 仅单点摘要，未与渠化层相位联动。
4. **叙事同步**：地图动作与 Process 旁白/语音**同时全量出现**，缺少分拍揭示（sticky reveal 仅约束侧栏，未约束地图）。

## 目标

在 **不违反 docs/rule.md 约束 19**（前端禁止合成几何/指标）前提下，建立「**镜头语言 + 分层标注 + 分拍编排 + 平滑过渡**」四件套，使诊断后地图呈现**连贯、丝滑、可跟读**。

### G1 · 镜头语言升级（运镜）

| 幕 | 现状问题 | 目标运镜 |
|----|----------|----------|
| act3 溢出验证 | 与 act4 同 zoom/pitch，无进口聚焦 | 下钻至 18 后 **微推（micro-dolly）** 至问题进口 bearing；pitch 0→15 缓入 |
| act4 下游承接 | 未看向主要下游节点 | **fitBounds(目标+主要下游)** 或 `panTo` 下游；保留目标路口于构图偏左 |
| act5 溯源 | 仅 flyTo 中心 | **fitBounds(溯源网络)**；默认展开最大占比标签；粒子与语音同步启停 |
| act6 成因 | 与 act3/4 视觉同质 | 回切进口 **close-up**（zoom 18.5 上限）+ 主因标注 **sequential reveal** |
| act7 策略 | 控制点 marker 稀疏 | **fitBounds(控流+保护+协调路径)**；pitch 45° 展示控制范围面 |
| act8 方案 | 单 marker 摘要 | 保持渠化级，**按 phase_changes 逐条高亮** 对应进口/相位 |
| act9 反馈 | 与 act5 同质 | 抬升 17 + 保留溯源残影淡出，非硬 clear |

### G2 · 视觉标注体系

- 统一 **AnnotationSpec** 类型：`callout`（气泡）/ `badge`（角标）/ `connector`（连线）/ `zone`（半透明面）/ `pulse`（呼吸点）。
- 标注内容**全部来自后端 map_scenes 或 channelization_map 真源**；前端只做布局与动画。
- act3–4：`diagnosis_compare` 扩展为 **双节点 callout + 对比连线 + 指标 diff 色条**。
- act6：`cause_spatial.annotations[]` 增加 `anchor`（approach/downstream/case）与 `layout_offset`，避免堆叠。
- act7：`control_scope_map` 增加 **risk_boundary polygon**（若有真实 coord 序列）与 **coordination_paths** 发光双层线。
- act8：`plan_preview.phase_changes[]` 与渠化 `phase_stage_id` 映射，在对应 arm 上渲染 **Δ绿信比 badge**。

### G3 · 分拍编排（Map Choreography）

- 新增 `MapChoreographer`：订阅 `currentAct` + Process 打字进度 / 语音 cue，按 **beats[]** 分时触发 overlay reveal。
- 每幕 beats 定义在 `frontend/src/config/mapChoreography.ts`（纯编排，不含业务数据）。
- 示例 act4：`[0ms 镜头 fitBounds] → [400ms 目标 callout] → [800ms 下游 callout] → [1200ms 对比连线]`。
- `prefers-reduced-motion`：beats 压缩为 0ms 全量展示。

### G4 · 平滑过渡（Overlay Lifecycle）

- 替换 `applyScene` 开头 `clear()` 为 **OverlayStack**：按 layer id 差量更新；移除层 300ms 淡出，新增层 350ms pop-in（已有 `marker-pop` 可复用）。
- 跨幕 **persistent layers**：目标路口虚线框、channelization L0 道路面可在 act3–8 保留底图，仅换证据层。
- 流式 `diagnosis` 补齐：仅 **patch** 变更的 overlay id，不重绘整幕。

## 非目标

- 不实现 R5 车辆轨迹（亚楠侧仍无数据）。
- 不改动 Skill 核心推理；后端仅扩展 map_scenes **呈现字段**（坐标/标签/phase 映射均来自已有 PG 真源）。
- 不重做 MapLibre 迁移（继续 AMap 2.0）。
