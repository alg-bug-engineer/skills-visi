# 需求 4：前端就绪与剧本补齐

## 需求概述

在需求 1～3 已交付五 Skill 流水线、生产化数据真源、经验沉淀闭环的基础上，对照 `docs/剧本.md` 与 2026-07-07 符合性检查结果，补齐**前端对接所需 API 契约、分步执行能力、PG 数据加载入口、剧本字段缺口与集成文档**，使前端可在不依赖 mock 全量动画的前提下，按九幕真实推进联调。

本需求**不包含前端 UI 实现**（仍由独立前端仓库/迭代负责），但须达到「后端契约稳定、字段可映射、失败态可展示、分步可调用」的前端就绪标准。

## 与需求 3 的边界

| 需求 3（已完成） | 需求 4（本需求） |
|-----------------|-----------------|
| NLU 三类经验拆分与 jsonl 沉淀 | 经验/案例的**列表查询 API**（供第九幕近期案例区） |
| accept/reject 写入 `plan_feedback.jsonl` | 「修改后再生成」与分步 rerun 契约 |
| 成因/方案阶段经验引用字段 | 策略 LLM 字段完整透出、顶层 `plan.recommendation` |
| 剧本第九幕数据面 | 第九幕**交互 API** 扩展（modify / cases 列表） |
| 一次性 `POST /agent/run` 全量返回 | **分步执行** + 可选进度推送，对齐剧本底部任务栏 |

| 测试基线 | 64 passed | 新增用例后全绿 |

## 需求条目

### 1. 公开响应字段补齐（P0）

对齐 `docs/剧本字段-API对照.md` 已标注缺口，**不得**以文案或 LLM 自由发挥替代结构化字段。

| 剧本/文档缺口 | 要求 |
|--------------|------|
| `plan.recommendation.rationale` | `build_public_run_response` 顶层 `plan` 块透出 `recommendation`（含 `recommended_plan_id`、`rationale`） |
| 策略 `recommended` / `hard_constraints` / `trigger_exit_rules` | `strategy_generation` artifact 与 `phases.strategy.strategy` 完整包含；LLM 输出经确定性合并，禁止丢弃 |
| 失败态 `available` / `reason` | 各阶段失败时公开响应保留已执行 `phases` + `phase_results`，文档约定前端展示规则 |

**验收**：`tests/test_api.py` 与新增契约测试断言上述路径存在且类型正确。

### 2. 分步执行 API（P0）

剧本要求：点击发送后底部任务栏显示「执行中：问题理解」，并支持逐幕推进（第十一幕口播）。

| 能力 | 要求 |
|------|------|
| `skill_ids` | `POST /api/v1/agent/run` 请求体可选 `skill_ids: string[]`，限制为默认 pipeline 子序列 |
| `stop_after` | 可选 `stop_after: string`，执行至指定 skill 后停止（含该 skill），返回 `completed` 按实际执行结果计算 |
| 会话上下文 | 再次调用时通过 `task` 传入上轮 `artifacts` 摘要或完整 `task` 上下文，继续后续 skill（文档约定 schema） |
| `phase_results` | 每次响应均含已执行阶段耗时与错误，供底部任务栏渲染 |

**非目标**：本期不实现用户中断（cancel）服务端强杀；可文档说明前端 abort 仅取消 HTTP 请求。

### 3. PG 路口数据加载 API（P0）

第二、三幕依赖真实拓扑与指标；`load_intersection_from_pg.iter_checklist_load` 已存在但未暴露 HTTP。

| 端点 | 要求 |
|------|------|
| `POST /api/v1/intersection/load` | 入参：`inter_id` 或 `intersection_name`、时间片参数；出参：`task` 片段（`metrics`、`topology`、`signal`、`diagnosis_ticket` 补全字段）、`checklist_queries[]` |
| 进度（P1） | 同端点支持 `Accept: text/event-stream` 或 `GET .../load/stream`，按 checklist 项推送 `checklist_item` 事件后返回最终 `task` |
| 无 PG | 返回 `ok: false` + `reason`，禁止 fallback 到 demo |

加载结果须可直接作为 `POST /agent/run` 的 `task` 注入，使 `spatial_scene.available=true`（有拓扑时）。

### 4. scene-cognition 检查单摘要（P1）

移植 `references/intersection/scene-cognition` 检查单逻辑（禁止 import references），在诊断阶段输出：

| 字段 | 路径 | 说明 |
|------|------|------|
| 场景报告 | `phases.diagnosis.scenario_report` | 六维或检查单维度的 `status` / `summary` |
| 问题条目 | `phases.diagnosis.scenario_report.issues[]` | `item_id`、`label`、`status`、`summary` |

成因分析可引用 `issues[]` 作为 `data_gaps` 补充，不替代 `cause_scores` 确定性评分。

### 5. 第九幕 API 扩展（P1）

| 能力 | 要求 |
|------|------|
| 修改后再生成 | `POST /api/v1/agent/plan/regenerate`：入参 `trace_id`、`base_task`、`modification`（文本或结构化 patch），从 `strategy_generation` 或 `plan_generation` 起重跑 |
| 近期案例列表 | `GET /api/v1/agent/cases`：合并只读 `knowledge_qa` 摘要 + `plan_feedback` 推荐/风险案例，支持 `problem_type`、`inter_id` 过滤 |
| 执行效果 / 专家评价 | **非目标**（仍归 `evaluation-feedback` Skill，单独需求） |

### 6. 前端集成文档（P0）

新建 `docs/前端集成指南.md`，须包含：

1. 演示环境 vs 生产环境变量矩阵（`LLM_MOCK`、`ALLOW_DEMO_FALLBACK`、`PG_DSN`）
2. 剧本示例句的完整 request/response JSON 样例（可引用 `tests/fixtures`）
3. 分步调用时序图（首次 intent → 注入 load → diagnosis → … → plan）
4. `completed=false` 时各 `phase_results[].errors` 与 `phases.*.available` 的 UI 约定
5. 地图字段约定：`lng`/`lat`、`highlight_path` 坐标序、 `map_scenes` 各 phase 用途

同步更新 `docs/剧本字段-API对照.md` 与 `docs/项目进度.md`。

### 7. 配置与约束

- 遵循 `docs/rule.md` 第 14–18 条：禁止 demo 静默 fallback；剧本字段为验收标准
- Skill 变更须有对应单元测试；API 变更须有 `tests/test_api.py` 或专用契约测试
- 开发前阅读 `bugs/`；详细计划见 `plans/4-前端就绪与剧本补齐.md`
- 分支命名：`yyyymmddhhmmss-4-前端就绪与剧本补齐`；禁止直接合入 `main`

## 反思：与 `docs/剧本.md` 的差异

| 剧本要求 | 需求 3 后现状 | 需求 4 目标 |
|----------|--------------|------------|
| 底部任务栏逐幕「执行中」 | 仅事后 `phase_results` | 分步 API + 文档约定前端轮询/SSE |
| 地图随阶段展开 | 全量一次返回 `map_scenes` | PG load + 分步返回，前端按幕切换 |
| 策略案例经验引用完整 | `not_recommended` 有，`recommended` 缺 | 策略字段补齐 |
| 推荐方案理由展示 | 仅 `phases.plan.recommendation` | 顶层 `plan.recommendation` |
| 修改后再生成 | 未实现 | `plan/regenerate` API |
| 近期案例区 | 无列表 API | `GET /agent/cases` |
| 执行效果回填 | 未实现 | **非目标**（evaluation-feedback） |
| 用户可随时中断 | 无 cancel API | **非目标**；文档说明客户端 abort |

## 验收标准

- [ ] `POST /agent/run` 支持 `skill_ids`、`stop_after`，分步执行测试通过
- [ ] `POST /intersection/load` 在有 `PG_DSN` 时返回可注入 `task`；无 PG 时结构化失败
- [ ] 顶层 `plan.recommendation` 含 `rationale`；`phases.strategy.strategy` 含 `recommended`、`hard_constraints`、`trigger_exit_rules`
- [ ] `phases.diagnosis.scenario_report` 含 `issues[]`（有 PG/注入数据时）
- [ ] `POST /agent/plan/regenerate` 可从指定阶段重跑并返回新 `trace_id` 或同 trace 续跑（文档约定）
- [ ] `GET /agent/cases` 返回推荐/风险/教科书案例分类列表
- [ ] `docs/前端集成指南.md` 发布且与 API 行为一致
- [ ] 全量 `pytest` 通过；新增用例覆盖 T4-01～T4-12（见开发计划）
