# 需求 30：案例/知识库多维结构化与精准相似检索

分支：`20260711160233-30-案例知识库多维结构化与精准检索`

## 背景

当前 `knowledge_qa.jsonl` 行业案例以「场景/诊断/方案/效果」四段长文本存储，相似检索主要依赖关键词命中（问题类型、溢出、上下游等），**维度过粗**。同样是「排队溢出」，干线协调场景与小路口单点场景的策略差异很大，但现有评分难以区分。

需求 27 R4 已补充 `similarity_dimensions` 等呈现字段，但底层仍从原文关键词推断，缺少统一的**结构化标签体系**与**查询侧多维画像**，导致相似案例选择与解释精度不足。

## 需求点

### 1. 案例多维标签 schema

新建 `app/data/intersection_config/case_tag_schema.yaml`，定义案例结构化维度与枚举值，至少覆盖：

| 维度组 | 示例枚举 | 用途 |
|--------|----------|------|
| `scope_type` | 干线协调 / 点位单口 / 短间距多路口 / 走廊区段 | 区分溢出处置层级 |
| `spatial_topology` | 短间距、蓄流不足、下游约束、上游冲击 | 拓扑相似 |
| `problem_type` | 排队溢出、饱和偏高、机非冲突、时空不均衡 | 问题形态 |
| `time_period` | 早高峰、晚高峰、平峰、学校相关 | 时段 |
| `traffic_pattern` | 左转集中、直行主导、混行冲突 | 流量特征 |
| `lane_organization` | 可变车道、左转专用、共用车道、渠化改造 | 车道组织 |
| `weather_event` | 雨雾、事故、施工、学校活动（可选命中） | 外部事件 |
| `strategy_actions` | 绿波协调、相位搭接、上游控流、防溢流保护、周期统一 | 可迁移策略 |
| `effect_outcome` | 排队下降、行程缩短、拥堵指数改善 | 效果类型 |

标签从案例原文**规则抽取**（只读 `knowledge_qa.jsonl`，不写回源文件），抽取逻辑集中在 `CaseTagExtractor`。

### 1.1 离线结构化沉淀（方案 A）

源库只读不动，启动前（FastAPI `lifespan`）离线生成旁路沉淀文件：

| 源库 | 沉淀文件 |
|------|----------|
| `data/knowledge_qa.jsonl` | `data/structured/industry_cases.jsonl` |
| `data/plan_feedback.jsonl` | `data/structured/intersection_cases.jsonl` |
| `data/user_experience.jsonl` | `data/structured/experiences.jsonl` |

- 另写 `data/structured/manifest.json`（生成时间、条数、源文件 mtime/hash）。
- 源未变则跳过重建（幂等）。
- 前端经 `GET /api/v1/agent/structured-catalog` **只加载**沉淀结果，不在前端做标签推断。
- 运行时相似检索优先读行业案例沉淀中的 `structured_tags`，避免每次请求重抽。

### 2. 查询侧多维画像

成因分析检索时，除 `problem_type` 外，从 `diagnosis_ticket` + `data_analysis_diagnosis` 构建 `query_profile`（时段、干线协调需求、下游场景、瓶颈类型等），与案例标签做**加权维度匹配**，而非纯文本子串。

### 3. 检索契约扩展

`CaseLibraryService.search_similar` / `search_case_cards`：

- 入参支持 `query_profile: dict | None`
- 出参卡片增加 `structured_tags`（按维度分组的标签列表）
- `similarity_dimensions` 改为**真实命中维度**（query ∩ case），附权重说明
- 评分透明：`dimension_scores` 可选透出（测试与调试）

### 4. 沉淀面板与 CauseCard 呈现

- CauseCard：展示案例 `structured_tags` chips（分组：场景层级 / 拓扑 / 策略）
- CasesCatalog 教科书分支透传 `structured_tags`
- tooltip 说明评分逻辑：「干线协调类溢出优先匹配 scope=干线协调 案例」

### 5. 与既有需求边界

| 关联 | 关系 |
|------|------|
| 需求 3 / 24 | 用户经验标签体系不变；本需求聚焦**行业案例库**检索精度 |
| 需求 27 R4 | 在 R4 呈现基础上补齐**底层结构化与匹配** |
| `knowledge_qa.jsonl` | **只读**；结构化标签运行时抽取或内存缓存 |

## 约束

- 遵循 `docs/rule.md`：分支开发、先写计划、单测同步、禁止 demo 造数、数据真源
- 无 LLM 参与标签抽取（确定性规则，可测可复现）
- 标签抽取失败时降级为空标签 + `available: false` reason，不阻断检索
