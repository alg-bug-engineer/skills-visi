# 需求23：以进口道+转向为约束，复刻 references/流量溯源 的 link 溯源效果

分支：`20260708210700-23-流量溯源进口道转向约束复刻`
参考：`references/流量溯源/`（`sniff/flow-trace-links-sniff.html`、`source/backend/services/correlate_sniff_map_service.py`）

## 一、背景与现象

演示路口「解放东路与奥体中路路口 / 奥体西路×经十路」的流量溯源可视化当前效果差，用户反馈两点：

1. **太短**：来向溯源只画出「目标 + 1 个上游路口」，且每个路口只保留 1 条进口 link，链路很短、信息量低。
2. **方向有问题**：画出的上游/走廊方向与真实进口道走廊不一致。

### 根因（已核对代码）

| 位置 | 现状逻辑 | 后果 |
|------|----------|------|
| `app/trace/map_scene.py::_select_primary_upstream` | 来向溯源 `_select_primary_upstream` 把多路口**塌缩为单一上游**（commit `67b0e19`「单一上游收敛」） | 走廊只剩 1 跳 → 太短 |
| `app/trace/map_scene.py::_filter_turn_links` | 每个路口只保留「进口 dir8 / 出口」1~2 条 link | 每路口没有完整「十字」→ 太短、方向单一 |
| `_correlate_peers`（upstream 分支） | 对每个 peer 跨 `cor_f_dir8/cor_turn` **求和聚合**，未以「进口道+转向」约束 correlate 行 | peer 选取与真实走廊不符 → 方向错 |

对照 `references/流量溯源`：BUG-002 记录中，按时段过滤后「西直行来向 rendered=19（18 上游 + 目标）」与参考一致；随后的「单一上游收敛」把它压回到 1，正是本次「太短」的直接来源。

## 二、参考逻辑（复刻目标）

参考 `correlate_sniff_map_service.py` 的口径：

1. **以进口道(dir8) + 转向(turn) 约束 correlate 行**（`incoming_row_in_corridor` / `outgoing_row_in_corridor`）：
   - 直行(turn=2)：`cor_f_dir8 == 进口dir8 且 cor_turn == 2`（同一进口道直行来向 = 真正沿走廊上游/下游）。
   - 左/右转：以「拓扑一跳」为锚，排除进口直行 OD 蔓延。
2. **多跳走廊链**：满足约束的 correlate peer 全量保留（不塌缩单点），按占比降序；主走廊(cor_f_dir8==dir8 & cor_turn==2) 标 `in_main_corridor`，拓扑一跳标 `is_topo_anchor`。
3. **每个路口渲染完整 link「十字」**：target 与每个 peer 都取自身全部进/出口 link（真实 `dim_link_info.geom`），不再按转向裁到单条 → 链路更长、方向完整。
4. **方向由真实几何决定**：每条 link 用自身 WKT 折线，前端 `showDir` 呈现流向，不做前端合成（rule 19）。

## 三、目标（验收标准）

- R1 · **不再塌缩单一上游**：来向溯源渲染「目标 + 走廊多跳 + 其他来向 peer」，与参考 sniff 同量级（西直行来向恢复到 18 上游量级，受真实数据/时段/阈值约束）。
- R2 · **每路口完整十字**：target 与 peer 均渲染其真实进/出口 link 全集，不再裁到单条；`stats` 反映 link 总数明显增加。
- R3 · **方向正确**：主走廊沿真实进口道方向延展，`in_main_corridor` / `is_topo_anchor` 与参考一致；进口道+转向约束落到 correlate 行级。
- R4 · **数据真源**：全部 path/坐标/占比来自 PG（`dim_link_info.geom` / `dim_inter_info.geom_center` / `flow_correlate`），无数据 `available:false`+`reason`（rule 16/19）；沿用 BUG-002 单时段过滤，禁止跨时段虚增。
- R5 · **测试同步**：更新反映旧「过滤/单点」行为的单测为新口径；新增多跳走廊 + 完整十字用例；`pytest tests/ -q`、前端 `npm test`、`npm run build` 全绿（rule 4）。

## 四、非目标

- 不改前端渲染层配色/交互契约（`renderSniffScene` 已按参考实现，主要是后端补足 intersections/links 数据）。
- 不改 `channelization_map` / `downstream_trace_map` / `arterial_analysis` 其他场景。
- 不重构 PG 取数管道为参考项目的 async service 架构；沿用现有 `pg_raw` + `_fetch_peer_link_geometry` live 取数路径。
- 左/右转走廊的深度递归治理树（参考 `upstream_governance_trace_service`）不在本需求范围。
