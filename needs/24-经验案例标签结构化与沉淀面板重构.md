# 需求 24：经验/案例标签结构化与「沉淀面板」重构

## 背景
左侧「理解面板」当前只呈现**本轮推演**从响应中派生的经验与相似案例（`experiencesByType` / `existingCases` 取自当前 `response`），本质是「检索结果的呈现」。这与产品定位不符：认知/诊断/方案经验、路口沉淀案例应是**智能体对历史沉淀的全量呈现**，体现「吸收 → 理解 → 使用 → 沉淀」的闭环。

## 需求点
1. **标签体系与结构化 + 去重**：对所有经验与案例增加结构化标签展示（路口、时段、问题类型、成因维度、策略动作等），优化显示逻辑，增加去重，避免重复条目。
2. **经验=历史全量呈现，非检索结果**：认知/诊断/方案经验是对历史存储结果（`data/user_experience.jsonl`）的呈现；经验绑定路口等标签；每次默认呈现所有已积累经验，不随本轮检索变化。
3. **路口案例=沉淀确认方案的全量呈现**：路口案例是所有路口过去「确认（接受）」方案的沉淀；若存在对应固化 skill，提供下载功能。所谓「检索」是**右侧闭环逻辑**中相似案例检索/经验使用的过程（不是面板上的搜索框）；右侧卡片「参考依据」点击跳转，需要能定位到面板中这些历史沉淀内容（路口沉淀案例 / 全部经验 / 全部行业案例）。
4. **面板重构与更名**：以「吸收 · 理解 · 使用 · 沉淀」闭环为出发点重构左侧面板；将「理解面板」文案更名为「沉淀面板」。保留两级结构（经验库 / 案例库 → 行业·路口）。

## 约束
- 遵循 `docs/rule.md`：分支开发、先写计划、单测同步、日志带 trace_id、禁止 demo 造数、数据真源。
- 前端只做呈现与本地过滤/去重，不合成业务数据（rule 19）；新增「全量经验」需后端提供真实接口。
- `knowledge_qa.jsonl` 只读；动态库（经验/反馈）只增不改既有沉淀语义。

## 验收
- 「沉淀面板」标题为「沉淀面板」，进入即（不依赖推演）展示全部历史经验与全部路口确认案例，条目带结构化标签且无重复。
- 路口案例含固化 skill 的条目出现「下载技能包」入口，点击可下载 zip。
- 本轮新吸收/新确认的条目在全量列表中置顶并高亮标记。
- 右侧卡片「参考依据」点击可跳转定位到面板对应历史条目。
- 新增/更新后端与前端单测全部通过。
