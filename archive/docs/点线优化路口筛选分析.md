# 点/线优化路口筛选分析

> 落库时间：2026-07-09  
> 关联 SQL：`analysis/溢流路口统计优化.sql`（本地）、`scripts/six_intersections_supplement.sql`  
> 全库扫描脚本：`scripts/screen_point_line_intersections.py`  
> 结果目录：`data/screening/point-line-latest/`（每次运行带时间戳子目录）

---

## 1. 背景与目标

信控优化中常见两类相邻路口组合：

| 类型 | 名称 | 优化思路 | 代表 |
|------|------|---------|------|
| **Type 1** | 点优化 | 当前路口某转向溢流/过饱和，**直接下游仍有承接空间** → 可局部增绿、流量重分配 | 「加绿以后，车有没有地方去？」 |
| **Type 2** | 线优化 | 当前路口有问题，**下游也 blocked** → 只能上游截流、干线协调、防溢流相位 | 「本路口 + 下游共同堵」 |

本分析定义量化指标、聚合口径、筛选阈值，并支持从 PostgreSQL 全库扫描候选路口对。

## 2. 核心指标口径（禁止直接读 rid_length_m）

### 2.1 进口道长度 / 库容

来源：`analysis/溢流路口统计优化.sql` 中 `direction_spacing` CTE：

```sql
-- 每个路口 × 进口方向：entrance slink 的 MIN(length_m)，且 >= 50m
adjacent_inter_spacing_m
```

- **禁止**使用 `rid_length_m`、`f_dist_m` 作为溢流分母（易将库容压到 7–15m，产生假溢流）。

### 2.2 溢流比 overflow_ratio

```
overflow_ratio = queue_len_avg / adjacent_inter_spacing_m
```

- 数据源：`xianchang.dwd_tfc_inter_dir_perf_5min`（5 分钟时序）
- 粒度：`(stat_time, inter_id, eight_direction, turn_dir_no)`
- 阈值（对齐 `app/metrics/traffic.py`）：
  - `≥ 0.8`：预警（queue_ratio_warning）
  - `≥ 1.0`：明确溢流（queue_ratio_spillback）

### 2.3 饱和度 / 绿灯利用率

- 数据源：`xianchang.dws_turn_saturation_5min_mm`、`dws_turn_green_utilization_5min_mm`
- 粒度：周内典型日 `day_of_week` + `step_index`（5 分钟槽位）
- 晚高峰窗口：`step_index` 204–228（17:00–19:00）

### 2.4 方向编码

| 字段 | 含义 |
|------|------|
| `dir8_code` (0–7) | 拓扑表八方向进口 |
| `eight_direction` (1–8) | 高德 DWD 表方向，`eight_direction = dir8_code + 1` |
| `turn_dir_no` | 1=左转，2=直行，3=右转 |

## 3. 走廊配对逻辑

与 `app/trace/topology.py::exit_dir8_for_turn` 一致：

```
目标：(target_inter, entrance_dir8, turn_dir_no)
出口：exit_dir8 = f(entrance_dir8, turn)
      直行: (d+4)%8；左转: (d+2)%8；右转: (d+6)%8
下游：exit link 的 t_inter_id（仅信控路口 is_signalized=1）
下游接收：receiving_dir8 = (exit_dir8 + 4) % 8
          receiving_eight_direction = receiving_dir8 + 1
```

**示例（奥体中路×坤顺路 南进口直行）**：

- 出口朝南 → 下游：解放东路×奥体中路
- 下游从北进口接收 → 评估其北进口直行指标

## 4. 下游「能否承接」判定

不能只看「有排队空间」或「高饱和」单项，需组合判断（对齐 `assess_downstream_capacity` / `classify_release_bottleneck`）：

```python
downstream_blocked = (down_overflow_max >= 0.8) OR (down_sat_max >= 0.85)
downstream_slack   = NOT downstream_blocked
```

| 状态 | 溢流比 | 饱和度 | 信控含义 |
|------|--------|--------|---------|
| A 理想承接 | < 0.8 | < 0.85 | 可适度增绿 |
| B 暂存型 | < 0.8 | ≥ 0.85 | 仅可短脉冲，不宜持续加绿 |
| C 回溢型 | ≥ 0.8 | 任意 | 禁止向下游加压 |
| D 出口不畅 | 低 | 高但绿利用低 | 先查出口/渠化，非简单加绿 |

**「有排队空间但高饱和」属于 B 类**，不算理想 Type 1。

## 5. 分型规则

### 5.1 目标侧「有问题」

满足其一（晚高峰窗口内 **MAX**）：

- `target_overflow_max ≥ 0.8`
- `target_sat_max ≥ 0.9`
- `target_sat_max ≥ 0.8` 且 `green_util_max ≥ 0.85`（高需求且在用绿灯）

### 5.2 分型

| screen_type | 条件 |
|-------------|------|
| **TYPE1_POINT** | target_problem AND downstream_slack |
| **TYPE2_LINE** | target_problem AND downstream_blocked |
| WEAK_TYPE1 | overflow_max ≥ 0.3 AND downstream_slack（未达严格溢流） |
| WEAK_TYPE2 | overflow_max ≥ 0.3 AND downstream_blocked |
| EXPORT_BLOCKED | 高饱和 + 低绿利用 + 低溢流 |
| UNKNOWN_DOWNSTREAM | 目标有问题但下游无 DWD 排队数据 |
| OTHER | 其余 |

### 5.3 当前演示案例口径

受现阶段真实数据覆盖限制，演示案例采用 5.1 的窗口峰值规则，不额外要求排队均值或持续切片数。该口径用于讲解点/线优化决策链，不代表生产告警标准。限制与后续升级条件见 `docs/峰值口径演示说明.md`。

## 6. MAX vs AVG 使用原则

| 用途 | 统计量 | 原因 |
|------|--------|------|
| **库内筛案例** | 时段内 **MAX** | 捕捉最坏 5 分钟，不漏典型溢流 |
| **持续性校验** | **mean** 或 P95 | 过滤单点噪声（如平峰末一个切片） |
| **目标-下游配对** | **同窗口 MAX** | 保守估计，防止错配时段 |
| **报告展示** | MAX + mean 并列 | 兼顾峰值与常态 |

### 聚合层级

```
原子行 (5min×进口×转向)
  → 转向级 MAX/MAN（GROUP BY eight_direction, turn_dir_no）
  → 走廊对级（映射 exit → 下游接收进口）
  → 分型 TYPE1 / TYPE2
```

**路口级分时段峰值** = 该时段所有原子行的 `MAX(ratio)`，不一定等于「转向全天峰值」——最坏时刻可能落在时段外。

## 7. 六路口样本结论（2026-07-09）

| 路口对 / 走廊 | 分型 | 说明 |
|--------------|------|------|
| 奥体中路×坤顺路 → 解放东路×奥体中路（南直行） | **Type 2** | 目标溢流 0.36–0.53，下游饱和 **2.74** |
| 坤顺路×奥体西路 → 礼耕路岔口（西直行） | 弱 Type 1 | 下游余量大，目标溢流未达 0.8 |
| 坤顺路×奥体西路 **北左** → 坤顺×礼耕（东出口） | **Type 1（Case A）** | 饱和度峰值约 1.35；下游 slack。排队比均值较低，按峰值演示口径入选 |
| 解放东路×奥体中路（北直行） | 高饱和低溢流 | 饱和 2.74，溢流 0.37 → 出口/能力瓶颈 |
| 解放东路×奥体西路 | 无法判定 | **无 DWD perf 数据** |
