# 需求 35：目标进口全转向下游一跳溯源与可视化

> 状态：已完成（2026-07-14）

## 背景与目标

当前下游一跳溯源只按诊断票据中的单一 `movement` 构建。用户只指定目标进口道时，票据默认直行，导致左转、右转的直接下游及承接能力不会呈现。

本需求以“目标进口道”为分析范围，在不改变目标问题转向指标口径的前提下，同时输出左转、直行、右转的一跳真实去向，帮助判断目标路口绿灯调节对各直接下游的影响。

## 设计

1. PG 拓扑层
   - 保留现有 `downstream_nodes` 作为目标问题转向的兼容字段。
   - 新增 `downstream_turn_nodes`，按左转、直行、右转分别从 `trace_geometry` 的真实出口 link 与 `flow_correlate` 占比构建。
   - 每条节点记录携带目标转向、出口方向、下游承接进口、真实路径及数据来源；无真实几何时不造路径。
2. 指标富化层
   - 对 `downstream_nodes` 与 `downstream_turn_nodes` 去重后逐“下游路口 + 承接进口 + 转向”加载真实 PG 指标。
   - 缺指标时保持 `metrics_available=false` 与结构化原因，不回落到 0。
3. 诊断输出层
   - `downstream_trace.turn_traces` 输出目标进口左/直/右三类存在真实拓扑的结果。
   - 增加 `selected`、`turn_label`、`exit_dir8`、`receiving_dir8/label`、`metrics_available/reason` 等可视化契约。
   - `movement_summary` 按三转向给出可用性、下游数量和受阻数量；治理结论继续以票据目标转向为主，避免其他转向污染现有配时护栏。
4. 可视化层
   - 地图场景完整透传三转向字段与承接指标。
   - 前端按左/直/右显示标签并确保同一下游的多转向边不会因 ID 冲突被覆盖；仅消费后端真实几何。
5. 文档契约
   - 更新数据分析 Skill 的规则说明，明确全转向一跳输出与兼容/治理口径。

## 单元测试

- 后端：
  - 同一进口道按三种出口方向构建真实一跳拓扑，校验路径、出口方向、承接进口及占比绑定。
  - 单转向兼容字段保持不变。
  - 下游 trace 输出三转向、选中态、汇总与目标转向治理结论。
  - 地图场景透传三转向关键字段。
  - 指标富化覆盖全转向节点且缺失时结构化降级。
- 前端：
  - 三转向路径均进入下游拓扑；同一下游多转向不覆盖。
  - 标签优先呈现左转/直行/右转及真实占比。
- 回归：运行相关 pytest、前端 Vitest 与构建。

## 回滚

回滚本需求提交即可。`downstream_nodes`、现有 `turn_traces` 基础字段及目标转向治理口径均保持兼容，不涉及数据库结构变更。
