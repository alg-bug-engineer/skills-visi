# 计划 24：经验/案例标签结构化与「沉淀面板」重构

对应 `needs/24-经验案例标签结构化与沉淀面板重构.md`。分支：`20260708224146-24-经验案例标签结构化与沉淀面板重构`。

## 一、总体思路
面板由「本轮检索结果呈现」升级为「历史沉淀全量呈现」：
- 经验（认知/诊断/方案）来自 `data/user_experience.jsonl` **全量**（去重、按类型分组、按路口标签绑定）。
- 路口案例来自 `data/plan_feedback.jsonl` 中**全部确认（accept）+ 风险（reject）**记录（跨路口），并 join `data/skills/*` 固化技能提供下载。
- 行业案例仍为只读 `expertKnowledge.json` 结构化全量（保留既有折叠/局部过滤，不属于业务检索）。
- 右侧闭环卡片「参考依据」通过既有 `open-case-library` 事件跳转到面板对应条目（经验 / 路口案例 / 行业案例）。
- 本轮推演新吸收/新确认条目在全量列表置顶并高亮，体现吸收闭环。

## 二、后端改动

### 2.1 ExperienceLibraryService.list_all（app/services/experience_library.py）
- 新增 `list_all(experience_type: str | None = None) -> list[dict]`：返回全部记录（不打分），按 `recorded_at` 倒序；读时按内容签名去重（复用 `experience_service.experience_signature` 口径，容错重复历史行）。
- 每条输出：`record_id, recorded_at, trace_id, experience_type, content, source_span, tags, inter_id, intersection_name`（`inter_id/intersection_name` 从 `tags` 或 `diagnosis_ticket_snapshot` 补齐）。

### 2.2 路由 GET /api/v1/agent/experiences（app/api/routes.py）
- 返回 `{"experiences": {"cognitive": [...], "diagnostic": [...], "solution": [...]}, "total": n}`。
- DI：新增 `get_experience_library_service`（`ExperienceLibraryService(settings.user_experience_abs_path)`）。
- 日志带 trace_id（请求级生成或复用）。

### 2.3 路口案例全量 + skill join（app/services/feedback_service.py / cases_catalog_service.py）
- `PlanFeedbackService.search_accepted_plans` / `search_rejected_patterns`：返回增加 `inter_id`、`intersection_name`、`time_period`（取自 `diagnosis_ticket`）。保持向后兼容（新增字段）。
- `CasesCatalogService`：
  - 构造注入 `SkillSolidificationService`（可选，`None` 时不 join）。
  - recommended/risk 分支：`problem_type=None` 时返回全量（不再强制默认问题类型）；补充 `inter_id/intersection_name/time_period`。
  - recommended：按 `inter_id` join 固化技能列表（`list_skills()`），命中则附 `skill: {skill_id, download_url}`。
  - 去重：recommended 以 `(inter_id, strategy_applied, time_period)` 归并，保留最新；risk 以 `(inter_id, rejection_reason)` 归并。
- 路由 `get_cases_catalog_service` 注入 `SkillSolidificationService`；`limit` 上限提升（默认全量场景前端传 100）。

## 三、前端改动

### 3.1 API（frontend/src/api/endpoints.ts + types.ts）
- 新增 `listExperiences()` → `GET /agent/experiences`；MOCK 回放 fixture。
- `listCases` 增补返回类型（`inter_id/intersection_name/time_period/skill`）。
- 新增类型 `StoredExperience`、扩展 `CaseItem`。

### 3.2 Store（frontend/src/stores/presentation.ts）
- 新增 state：`precip: { experiences: {cognitive,diagnostic,solution}, interCases: CaseItem[], loaded, loading }`。
- 新增 action `loadPrecipitation(force?)`：拉取全量经验 + 路口案例（recommended+risk），去重；面板挂载即调用；accept/solidify 完成后 `force` 刷新。
- 新增 getter `precipExperiencesByType`：全量历史 + 本轮标记（`isFresh`，凭本轮 `response` 的 `experiencesByType` 内容匹配置顶）。
- 新增 getter `precipInterCases`：全量路口案例 + 本轮 `existingCases` 标记新鲜（凭 trace_id/plan_id）。

### 3.3 面板重构（frontend/src/panels/UnderstandingPanel.vue）
- 标题「理解面板」→「沉淀面板」；副标题「吸收 · 理解 · 使用 · 沉淀」。
- 保留两级结构：经验库（认知/诊断/方案）/ 案例库（行业/路口）。
- 经验条目：结构化标签 chips（路口/时段/问题/成因/策略），全量呈现，本轮高亮置顶。
- 路口案例：全量确认/风险案例，category 徽标 + 标签 chips；recommended 且有 skill 时展示「下载技能包」。
- `onMounted` 触发 `store.loadPrecipitation()`；不再以 `experienceReady/casesReady` 门控（改为 loading/empty 提示）。
- 保留 `open-case-library` 跳转：路口案例 refId 用 `inter-case-<case_id>`；经验可扩展 `open-experience`（可选）。
