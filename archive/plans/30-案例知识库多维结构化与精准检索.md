## 一、总体思路

1. **Schema**：`case_tag_schema.yaml` 定义维度、枚举、中文关键词映射。
2. **抽取**：`CaseTagExtractor.extract(case)` 从四段文本规则打标，加载时缓存。
3. **画像**：`build_query_profile(ticket, diagnosis)` 从本轮工单与诊断输出查询向量。
4. **评分**：`score_case_tags(case_tags, query_profile)` 加权求和 + 命中维度列表。
5. **接入**：`cause-analysis` 传入 diagnosis；`CaseLibraryService` 统一出口；`CasesCatalogService` 透传标签。

## 二、后端改动

### 2.1 新增 `app/data/intersection_config/case_tag_schema.yaml`

维度与关键词映射（节选）：

- `scope_type.arterial_coordination`: 绿波, 协调, 干线, 公共周期, 相位差
- `scope_type.point_intersection`: 单点, 单口放行, 渠化改造
- `scope_type.short_spacing_multi`: 短间距, 相距, 50m, 150m, 两路口

### 2.2 新增 `app/services/case_tag_extractor.py`

- `load_schema()` 读 yaml
- `extract_tags(case: dict) -> dict[str, list[str]]`
- `build_query_profile(ticket, diagnosis) -> dict[str, list[str]]`
- `score_match(case_tags, query_profile) -> tuple[float, list[dict]]`

权重（可配置于 schema）：

| 维度 | 权重 |
|------|------|
| problem_type | 3.0 |
| scope_type | 2.5 |
| spatial_topology | 1.5 |
| time_period | 1.5 |
| strategy_actions | 1.0 |
| traffic_pattern | 0.8 |
| lane_organization | 0.8 |
| weather_event | 0.5 |
