# 开发计划：闭环UI优化与运行数据/案例库增强

关联需求：`needs/13-闭环UI优化与运行数据案例库增强.md`
分支：`20260708094040-13-闭环UI优化与运行数据案例库增强`

## 一、目标与范围

在不交换现有两栏布局的前提下，完成四项 UI 优化并补齐后端富指标透传：
- R1 诊断工单卡 → 无序列表 + 更多 NLU 字段（含原始问题）。
- R2 案例库 → 行业案例（`expert_knowledge.md` 构建期 JSON，全量结构化 + 搜索）/ 路口案例（沉淀 + 相似案例）。
- R3 运行数据卡 → 逐进口/逐转向饱和度、绿灯利用率、延误指数、服务水平、方向失衡（后端透传）。
- R4 新增问题验证卡 + 治理策略卡（参考依据可点击定位案例）。

范围文件（改动/新增）：
- 前端：`frontend/src/cards/DiagnosisTicketCard.vue`、`DataMetricsCard.vue`、新增 `ProblemVerificationCard.vue`/`GovernanceStrategyCard.vue`、`frontend/src/panels/UnderstandingPanel.vue`、`frontend/src/panels/ProcessPanel.vue`、`frontend/src/api/types.ts`、`frontend/src/stores/presentation.ts`（getter/事件）、新增 `frontend/src/data/expertKnowledge*.ts`、新增解析脚本 `frontend/scripts/parse-expert-knowledge.mjs`、`frontend/src/mock/run_1_fixture.json`。
- 后端：`skills/data-analysis-diagnosis/scripts/analyze_overflow.py`、`app/data/pg_adapters.py`（如需保留富指标）、`app/api/response_builder.py`（如需透传）、`skills/cause-analysis`/`strategy-generation`（参考依据字段，如需要）。
- 测试：`frontend/tests/unit/*`、`tests/test_diagnosis_rich_metrics.py`（新增）等。

不改动：地图图层、方案生成配时链路、需求 12 成果。

## 二、数据流（目标）

```
后端 PG 装载(_aggregate_metrics: movement_saturation / imbalance_index / los; raw.turn_saturation/green_utilization/evaluation; signal.cycle/time_plan_count)
  └─ analyze_overflow 透传 → diagnosis.metrics.{by_approach,by_movement,imbalance_index,los,approach_count,lane_count}
      + diagnosis.timing_profile.{cycle_s,time_plan_count}
      + diagnosis.problem_regularity.{recurring,periodic,basis}(派生)
  └─ response_builder → RunResponse.phases.diagnosis
      └─ 前端 types.ts → DataMetricsCard(R3) / ProblemVerificationCard(R4)

构建期: frontend/scripts/parse-expert-knowledge.mjs (读 data/expert_knowledge.md)
  └─ 生成 frontend/src/data/expertKnowledge.json → UnderstandingPanel 行业案例(R2)

治理策略卡 参考依据 chips → 派发 open-case-library{tab, refId} → UnderstandingPanel 切 tab + scrollIntoView 高亮(R4)
```

- 新增「诊断范围」= `t('diagnosis_scope', tk.diagnosis_scope)`（缺失降级 `—`）；保留对象/路口(+inter_id)/时间(period)/方向转向/问题/治理目标/约束/解析置信度+匹配方式。

### 步骤 2（R2-数据）：expert_knowledge.md 构建期解析脚本
文件：新增 `frontend/scripts/parse-expert-knowledge.mjs`
- 读取 `../data/expert_knowledge.md`，按层级解析：`## 场景`（名/场景ID/案例数/描述）→ `### 典型问题: X`（出现频次/典型表现[]）→ `#### 治理方案: Y`（频次/关键措施[]/适用条件/注意事项/代表案例[{id,title,snippet}]）。
- 输出 `frontend/src/data/expertKnowledge.json`：`[{scene, sceneId, caseCount, desc, problems:[{name, freq, symptoms:[], schemes:[{name, freq, measures:[], applicable, caution, cases:[{id,title,snippet}]}]}]}]`。
- 在 `frontend/package.json` 增加 `"gen:cases": "node scripts/parse-expert-knowledge.mjs"`，并在 `predev`/`prebuild` 或 README 注明先执行（保持产物入库，构建不强依赖 md 存在）。
- 测试：`frontend/tests/unit/expert-knowledge-parse.test.ts`（对一段样例 md 断言解析出场景/问题/方案/代表案例结构）。
- Run: `npm run gen:cases` 生成 JSON；`npm test -- expert-knowledge-parse`；Commit（含生成的 JSON）。

### 步骤 3（R2-UI）：案例库子 tab 重构为 行业案例 / 路口案例

- 路口案例：沿用 `store.existingCases`（沉淀 + 相似案例），保留标题/相似度/措施/结果/经验，补 `case_id` 展示。

- 测试：`frontend/tests/unit/understanding-panel-cases.test.ts`（断言行业案例渲染 19 场景数量、搜索过滤生效、路口案例渲染现有 mock 案例）。
- Run: `npm test -- understanding-panel-cases`；Commit。

### 步骤 4（R3-后端）：透传逐进口/逐转向富指标 + 配时画像

## 九、风险

1. **`011wwe28ctu00001` 快照 `turn_perf` 为空**：逐转向 queue/delay 可能取不到；以 `turn_saturation`/`evaluation` 为主，缺失字段显式降级，不编造。

4. **点击定位 DOM 时序**：案例库切 tab 后需 `nextTick` 再 `scrollIntoView`，注意折叠项需先展开。
5. **无 PG 本地环境**：真实重采可能阻塞，按需求 11/12 先例记录阻塞，用 mock 完成前端联调，不以 mock 冒充生产。
