# 开发计划：4-前端就绪与剧本补齐

## 背景

需求 1～3 已交付五 Skill 流水线、生产化数据真源、经验沉淀与 64 项 pytest 基线。2026-07-07 对照 `docs/剧本.md` 的符合性检查表明：

- **内容链路**基本可支撑九幕叙事，但 API 为一次性全量响应，与剧本「分步执行、底部任务栏」交互不符
- **字段缺口**：`plan.recommendation`、`strategy.recommended` 等未在公开响应透出
- **数据入口**：`load_intersection_from_pg` 未 HTTP 化，第二幕 `spatial_scene` 生产联调困难
- **文档**：缺前端集成指南与失败态约定

本计划按 P0 → P1 分阶段交付，使前端可基于稳定契约开工。

## 目标

1. 公开 API 响应补齐剧本已标注缺口字段
2. `POST /agent/run` 支持分步执行（`skill_ids` + `stop_after`）
3. 新增 PG 路口加载 API，输出可直接注入 `task`
4. 诊断阶段输出 `scenario_report`（检查单摘要）
5. 第九幕扩展：`plan/regenerate`、`GET /agent/cases`
6. 发布 `docs/前端集成指南.md` 并更新字段对照表

## 非目标

- 前端 UI / 地图组件实现
- `evaluation-feedback` Skill（KPI 对比、执行效果回填、专家评价持久化）
- 服务端 cancel / 会话强杀（仅文档约定客户端 abort）
- 向量检索 / WebSocket 双向通道（SSE 为 P1 可选项）
- 向 `knowledge_qa.jsonl` 写入

## 阶段 G2：分步执行 API

### G2.1 请求 schema 扩展

`app/api/routes.py` — `AgentRunRequest`：

```python
class AgentRunRequest(BaseModel):
    user_input: str
    trace_id: str | None = None
    task: dict[str, Any] | None = None
    skill_ids: list[str] | None = Field(
        None,
        description="可选：仅执行指定 skill 子序列，须为默认 pipeline 的子序列",
    )
    stop_after: str | None = Field(
        None,
        description="可选：执行至该 skill_id 后停止（含）",
    )
```

### G2.2 AgentService / Executor

| 文件 | 变更 |
|------|------|
| `app/services/agent_service.py` | `run()` 透传 `skill_ids`、`stop_after` |
| `app/runtime/executor.py` | `stop_after`：执行到指定 skill 后 `break`；`completed` = 已执行段全部 success |
| `app/runtime/executor.py` | 校验 `skill_ids` 为 `DEFAULT_PIPELINE` 的子序列且顺序一致 |

**续跑约定**（写入集成指南）：

```json
{
  "user_input": "（可空，续跑时忽略）",
  "trace_id": "同一 trace",
  "task": {
    "diagnosis_ticket": {},
    "artifacts": { "intent_understanding": {}, "data_analysis_diagnosis": {} },
    "metrics": {},
    "topology": {},
    "signal": {}
  },
  "skill_ids": ["cause_analysis", "strategy_generation", "plan_generation"]
}
```

`SkillContext` 初始化时若 `task.artifacts` 存在，预填充 `context.artifacts`。

### G2.3 公开响应

- 分步执行仍走 `build_public_run_response`
- `completed`：若 `stop_after` 提前停止且已执行段均 success，可为 `true`（语义：本段完成）；文档说明与「全 pipeline 完成」区别，或增加 `pipeline_complete: boolean`（推荐新增，避免歧义）

```python
return {
    ...
    "pipeline_complete": all(skill in executed for skill in DEFAULT_PIPELINE) and all_success,
}
```

### G2.4 测试

| 用例 ID | 场景 | 断言 |
|---------|------|------|
| T4-01 | `stop_after=intent_understanding` | 仅 1 个 phase_result；含 `diagnosis_ticket` |
| T4-02 | `skill_ids` 仅 diagnosis | `phases.diagnosis` 存在；无 cause |
| T4-03 | 非法 skill_ids 顺序 | 400 或 422 |

## 阶段 G5：第九幕 API 扩展

### G5.1 plan/regenerate

```http
POST /api/v1/agent/plan/regenerate

{
  "trace_id": "原 trace",
  "user_input": "把东向西绿灯再增加 3 秒，但保持下游保护",
  "task": { "artifacts": { "...": "..." }, "modification_intent": "incremental_release" },
  "restart_from": "plan_generation"
}
```

实现：

- `AgentService.regenerate()` 合并 modification 到 `task`，从 `restart_from` skill 起调用 `run_pipeline`
- 默认 `restart_from=strategy_generation`（策略可能变化时）

### G5.2 GET /agent/cases

```http
GET /api/v1/agent/cases?problem_type=排队溢出&inter_id=...&limit=20
```

新建 `app/services/cases_catalog_service.py`：

| 来源 | 字段 |
|------|------|
| `knowledge_qa.jsonl` | `source= textbook`, `title`, `lesson`, `similarity` N/A |
| `plan_feedback.jsonl` accept | `source= recommended`, `trace_id`, `plan_id`, `tags` |
| `plan_feedback.jsonl` reject | `source= risk`, `rejection_reason` |

响应：

```json
{
  "cases": [
    { "case_id": "...", "category": "recommended|risk|textbook", "title": "...", "lesson": "..." }
  ],
  "total": 6
}
```

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 分步续跑 task schema 复杂 | 集成指南给完整 JSON；首期支持 `task.artifacts` 全量透传 |
| PG load 耗时长 | checklist SSE；前端先展示进度条 |
| scenario_report 与 references 漂移 | 单测对齐 checklist spec；不追求 100% 字段一致，先 issues[] |
| regenerate 护栏失效 | 强制重跑 `validate_plan_guardrails` |
| `pipeline_complete` 语义混淆 | 文档 + 字段显式区分 `completed` |
