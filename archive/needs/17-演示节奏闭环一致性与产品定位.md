# 需求17：演示节奏、处置闭环一致性与产品定位

分支：`20260708143000-17-演示节奏闭环一致性与产品定位`
前置：需求16（`9818169`）已合入 `main`。

## 一、背景

产品评审反馈三类问题：

1. **演示节奏过快**：除第一步等待后端 `intent` 外，第 2 幕起同 phase 多幕连播，领导来不及阅读。
2. **处置闭环「错觉」**：打字机阶段看到的内容，与自动折叠后再次展开看到的不一致——前者像后端结构化旁白，后者像前端排版后的摘要。
3. **产品定位表述**：项目以「排队溢出」为**典型分析场景**，但产品层不应强调「溢流/溢出智能体」，应统一为 **「交通信控智能体」**（或「交通信控决策系统」）能力叙事。

## 二、问题验证（已核对代码）

### 2.1 处置闭环「打字机 vs 折叠重开」不一致 — **已证实，属设计分叉而非数据错误**

`ProcessPanel.vue` 对每一幕使用**两套文案源**：

| 状态 | 渲染函数 | 内容形态 |
|------|----------|----------|
| 当前幕打字中 | `narrationFor(act, response)` → `useTyping.shown` | 多行逐步输出（含「正在解析…」「排队比 x｜饱和度 y」等推理步骤） |
| 当前幕打完 / 历史幕展开 | `summaryFor(act, response)` | **单行**汇总（如 `路口名｜排队溢出｜东向西直行`） |
| 历史幕折叠条 | `summaryFor` | 同上单行 |

关键模板分支（`frontend/src/panels/ProcessPanel.vue`）：

- 打字：`act.index === currentAct && !done` → `detail-lines` 展示 `shown`
- 否则：`step-summary` 展示 `summaryFor(...)` + 证据卡

因此用户感知为：

1. 打字时看到「过程旁白」（`narrationFor` 多行）；
2. 幕结束或折叠后再开，变成「结论条」（`summaryFor` 一行）+ 证据卡排版。

**根因**：`narrationFor` 与 `summaryFor` 在 `useTimeline.ts` 中独立实现，语义不同（过程 vs 结论），UI 却在同一区域切换，造成「换了一套话」的错觉。

**不在此需求归责的范围**：证据卡（`DiagnosisTicketCard` 等）本就是为结构化展示设计，与旁白切换叠加会加剧反差——属体验问题，非后端返回两套矛盾数据。

### 2.2 演示节奏 — **已证实**

链路：`useTyping`（默认 18ms/字）→ `onDone` → `onActTyped` → **750ms** → `tryAdvance()`。

- 第一步：常等待 `intent` phase SSE，体感慢。
- 第 2 幕起：同一 `diagnosis` phase 就绪后，幕 3–5 可在 `(打字时长 + 0.75s) × N` 内连播，证据卡仅停留约 0.75s。

Mock 模式 `MOCK_PHASE_DELAY=1400ms` 只拉长 phase 间隔，**不解决同 phase 内多幕连播**。

### 2.3 产品定位 — **已证实存在「溢出产品化」表述**

需调整的**产品壳层**（用户可见品牌，非剧本场景词）示例：

| 位置 | 现状 | 目标倾向 |
|------|------|----------|
| `App.vue` `brand__sub` | 排队溢出处置闭环 | 交通信控处置闭环 |
| `BottomDock.vue` 标题 | 排队溢出 · 智能决策控制台 | 交通信控 · 决策控制台 |
| `index.html` `<title>` | …排队溢出处置闭环 | …交通信控决策闭环 |
| `frontend/package.json` description | 交通智能体·排队溢出九幕演示 | 交通信控智能体·九幕演示（排队溢出为示例场景） |
| `frontend/README.md` 首行 | 排队溢出九幕演示前端 | 交通信控智能体演示前端 |

**保留不变**（典型问题域，非产品名）：

- `docs/剧本.md`、fixture 口播、`problem_type` 枚举「排队溢出」、案例库「排队溢出与回溢」等行业案例标题。
- 地图/证据红色告警样式（溢流红）作为**问题严重程度**视觉，非产品名。

`productCopy.ts` 已将「智能体」→「系统」；本需求进一步统一**产品称谓**为「交通信控」，避免「溢流智能体」类对外口径。

## 三、目标

### R1 · 演示节奏（组合策略，推荐）

- 打字间隔：`18ms → 28ms`（可配置 `VITE_DEMO_TYPING_MS`）
- 幕间停留：第 1 幕保持 `750ms`；**第 2 幕起 `2000ms`**（可配置 `VITE_DEMO_ACT_DWELL_MS`）
- `instant` 路径（测试 / `prefers-reduced-motion` / webdriver）不受影响

### R2 · 处置闭环文案一致

- 幕完成后**保留已打出的旁白全文**（按幕索引缓存），折叠后再展开仍显示同一套多行旁白，而非切换为 `summaryFor` 单行。
- `summaryFor` 仅用于：**折叠条**（`collapsed-summary`）与列表极窄态，或删除 expanded 态的 `summaryFor` 避免重复。
- 新增单测：某幕打字完成后展开/折叠/再展开，文本包含 `narrationFor` 末行关键字，且不意外回退为仅 `summaryFor` 短句。

### R3 · 产品定位文案

- 调整 R3 表中壳层文案；e2e 断言同步。
- 不批量改剧本、fixture 业务字段、专家案例库正文。

## 四、验收标准

1. 第 2 幕起自动播放明显变慢，领导可读完旁白 + 证据卡摘要。
2. 任意已完成幕：折叠 → 再展开，旁白与打字完成时一致（多行过程文案），无「换文」感。
3. 主页/顶栏/浏览器标题不再以「排队溢出」作为产品名；仍可用排队溢出作示例输入与场景分析。
4. `npm test` + `npm run build` 全绿；新增/更新单测覆盖 R1/R2/R3。

## 五、非目标

- 不改后端 SSE phase 节奏、不改 Mock `MOCK_PHASE_DELAY` 作为唯一手段。
- 不重写 `narrationFor`/`summaryFor` 生成逻辑（仅改展示策略）。
- 不改动地图图层、配时链路、需求16 布局成果。
